# Витрина кампаний бэктеста: спецификация (заказ оператора 04.10.2026)

Страница в домене бэктеста STL: ВСЕ проведённые кампании карточками, у каждой миниатюра кривой
доходности, по клику подробный отчёт лидера(ов) с большим графиком. Работа двух окон: ui-ux
(`frontend/`, `trader/api/`) делает страницу и ручки, backtests (`scripts/`, `docs/campaigns/`)
отдаёт данные и ведёт реестр. Спецификация общая, правки через письмо.

## Что видит оператор
- Витрина: сетка карточек. Карточка: название кампании, краткая идея/стратегия (1-2 строки),
  миниатюра кривой (ось X время, ось Y P&L), плашка статуса, две-три метрики (net, сделки, просадка),
  метка редакции («ред. 3 из 5»).
- Клик: карточка разворачивается (или открывается страница) в подробный отчёт: большой график лидера,
  таблица лидеров (топ-N со своими кривыми), параметры, окно данных, вердикт, ссылка на документ,
  цепочка редакций.
- Уникальный URL у каждой карточки: `/<домен бэктеста>/campaigns/<slug>` (точный вид маршрута SPA выберет
  ui-ux), открывается сразу в развёрнутом виде; ссылка живёт вечно (slug не меняется).
- Статусы: `done` (есть результат), `running` (идёт, прогресс `finished/total` из `agent_tasks`),
  `queued` (плашка «ожидает прогона»: пререгистрирована в реестре, заданий ещё нет или все queued),
  `no_curve` (кампания завершена, но кривой нет, показывать метрики и причину).
- Редакции: у кампании поле `family` (линия идеи) и `rev`; карточки одной линии связаны цепочкой
  «ред. 1 → 2 → 3», у каждой редакции строка «что изменили в условиях». На витрине по умолчанию
  свёрнуто до последней редакции линии, переключатель «показать все редакции».

## Рисунок графика (миниатюра и большой одинаково), как в TSLab
- Площадная кривая от нулевой оси: ВЫШЕ нуля зелёная, НИЖЕ нуля красная. Цвета мягкие, приглушённые:
  зелёный ≈ `#6fa77a` (заливка 30-35% прозрачности), красный ≈ `#c47a7a` (то же); линия кривой того же
  оттенка плотнее; нулевая ось тонкая серая. Смена цвета строго на y=0 (жёсткий стоп градиента или два
  clipPath), без плавного перехода.
- Миниатюра без осей и подписей, только кривая, нуль и подпись итога в углу. Большой график: оси, сетка
  едва заметная, подсказка по наведению (дата, P&L), масштаб по времени.
- Цвета как токены темы (светлая и тёмная), 10px минимальный шрифт (правило UI стандартов).
- Каждое окно с копируемым ID/URL в левом верхнем углу (правило оператора).

## Данные (поставляет backtests)
Реестр `docs/campaigns/registry.json` (в git, правит backtests), сборщик `scripts/campaign_showcase_build.py`
(запуск на хостере, результат только чтение для API):
- `data/campaign_showcase/index.json`: массив карточек `{slug, title, idea, strategy, family, rev,
  status, progress:{finished,total}|null, updated_at, headline:{net, trades, max_dd, window},
  thumb:[[ts, pnl],...≤200 точек]|null, verdict, doc, kind, unit, symbols, no_curve_reason}`.
  `kind`: `optimizer`|`research`; `unit`: `rub`|`points`|`pct` (для optimizer по `point_value` лучшего прогона:
  нет коэффициента или 1.0 = пункты); `symbols`: список инструментов окна данных или `null`;
  `no_curve_reason`: причина при `thumb: null`. Порядок в index.json: done/running с кривой (research раньше
  optimizer, свежие выше), затем queued, затем no_curve. Число карточек ≈ 540 (36 research + ≈506 optimizer,
  из них с кривой 35).
- `data/campaign_showcase/<slug>.json`: подробный отчёт `{…карточка…, leaders:[{rank, params, metrics,
  curve:[[ts,pnl],...≤1500], trades_n}], revisions:[{slug, rev, changes}], runs:[campaign_run, ...],
  data_window:{from,to,symbols}, notes}`.
- Единицы: `pnl` в рублях на указанный объём, поле `unit`; кампании в пунктах/процентах помечены `unit`,
  фронт подписывает ось по нему. Поля пустые, не выдуманные: нет кривой = `thumb: null` и причина `no_curve_reason`.
- Источники кривых: (1) кампании оптимизатора: `backtest_results.equity_curve` строк `<campaign_run>-bf<rank>`
  (бэкфилл топ-N, см. `reference_campaign_backfill`), (2) исследовательские кампании `gate/plc/exec`:
  посуточный net выбранной конфигурации из результатов i9. Где кривой нет и её нельзя получить без
  перепрогона, карточка `no_curve` и очередь на досчёт (решение оператора по стоимости).
- Служебные кампании (`SQL_NOT_SERVICE`, gate/plc/exec) показываются на витрине, но с меткой «исследование»
  и не зажигают «кандидат».

## Поля лидера: единица и доля прибыльных периодов (04.10.2026)
- `unit` (`rub`|`points`|null) и `unit_source`: `measured` - единица определена по сделкам перепрогона (net против
  gross_points x pv); null - единица неизвестна, тогда `unit` = null, `return_pct` = null, `buyhold_curve` = null.
  Значение `inferred` (по `point_value` строки лидерборда без перепрогона) не выдаётся: проверка
  `scripts/unit_heuristic_check.py` против измеренной единицы на 15 разных стратегий ошиблась в 7 (47%),
  у всех ошибок `point_value` = None. Эвристика «нет коэффициента или 1.0 = пункты» ненадёжна. Карточка:
  `unit`/`unit_source` берутся у лидера с перепрогоном, иначе null.
- `l_share` (0..1) и `l_share_source`:
  - `curve` - измерено: доля календарных месяцев (UTC) окна кривой перепрогона с плюсовым приростом net;
  - `leaderboard_windows` - оценка: windows_profitable / windows_total строки лидерборда. Это доля ОКОН
    перебора (нарезка одного прогона), а не месяцев; с `curve` несопоставима, сравнивать между собой нельзя.
  - null - нет ни кривой, ни окон.
- `score` = rf x net x l_share; при смеси источников `l_share` score сортирует лидеров, но сопоставим только
  внутри одного `l_share_source`.

## API (делает ui-ux, предложение)
`GET /api/v1/lab/showcase/campaigns` (index.json), `GET /api/v1/lab/showcase/campaigns/<slug>`; данные из
файлов сборщика, либо из таблицы, если ui-ux так удобнее (тогда сборщик пишет в неё). Кэш по mtime как у
пределов (`quik_limits.json`).

## Разделение работы
- ui-ux: маршруты и страница, компонент карточки, компонент графика (переиспользовать `EquityChart.svelte`,
  если ложится), API, тесты, стили, выкладка фронта. Решает транспорт данных и вид URL.
- backtests: реестр, сборщик, описания и идеи кампаний, цепочки редакций, статусы из очереди, вердикты
  с документов, досчёт кривых. Не деплоит.
- Открытые вопросы к ui-ux: (а) файлы или таблица; (б) формат маршрута; (в) нужен ли поиск/фильтр по
  инструменту и статусу на первой версии; (г) сколько карточек ожидается (посчитаем по реестру).
