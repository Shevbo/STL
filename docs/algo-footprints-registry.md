# Реестр отпечатков алгоритмов: дешифровка чужих стратегий по данным

Заказ оператора 30.09.2026: не искать «нашу» стратегию, а расшифровать, какими
алгоритмами торгуют крупные участники и манипуляторы на FORTS, и найти в
данных их след. Пересечение скользящих средних — самый примитивный пример
такого алгоритма; реестр ниже перечисляет семейства алгоритмов, след, который
каждое оставляет в цене/стакане/ленте, и способ этот след измерить с контролем
на случайность. Каждая строка реестра — отдельная проверка отдельным
исполнителем (Sonnet), протокол в конце файла.

## Реестр

Статусы: `идея` / `в работе` / `шум` / `след есть` / `торгуемо`. «След есть»
означает статистически отличимый от контроля отпечаток; «торгуемо» — эффект в
пунктах больше издержек круга (RI по стакану 9-12 пт/филл) и переживает
вторую половину данных. Строки с «след есть» без «торгуемо» ценны сами по себе:
они говорят, КТО на рынке, даже если на этом нельзя заработать напрямую.

## Протокол проверки одной строки (для исполнителя)

1. Модуль `trader/lab/footprints/<id>.py` с `run(arg: dict) -> dict`; загрузчики и
   контроли берутся из `trader/lab/footprints/common.py`, ничего не дублировать.
   Модуль добавляется в `agent/update_manifest.txt`. Считает i9 через очередь
   (kind=task), постановка как у `rr3` (`/tmp/submit_rr2.py` на хостере).
2. Единица измерения — пункты цены инструмента; в отчёте рядом с эффектом
   всегда стоит цена круга (RI 9-12 пт по стакану, комиссия по
   `trader/lab/commission.py`) и ATR минуты.
3. Контроль обязателен и должен сохранять структуру дня: перетасовка ВНУТРИ дня
   или перестановка ЦЕЛЫХ дней, никогда полная перетасовка ряда. Отчёт даёт
   p-value и 95% интервал бутстрапа.
4. Вторая половина данных — отдельная строка отчёта. Эффект, живущий на одной
   половине, — не эффект.
5. Ловушки, уже пойманные в этом проекте (каждая переворачивала вывод):
   заглядывание в будущее при выборе окна или группы; фантомные скачки через
   дыры непрерывного ряда (резать по времени, не по числу баров); контроль без
   дня недели; bid/ask-отскок на M1 close (проверять на mid); дубли сетки;
   среднее вместо медианы при тяжёлых хвостах; данные 2022-2025 запрещены,
   только 2026.
6. Отчёт исполнителя: цифры и что помешало. Без выводов о торгуемости, вывод
   делает окно после проверки fable.

### Каркас (`trader/lab/footprints/common.py`, образец `a4_bar_boundary.py`)

- Загрузка: `load_bars(key, since, until)` (бары `[ts,o,h,l,c,v]`), `load_book(key, since, until)` -> `(times, books)`; окно ISO-дата/epoch, until-дата включительно.
- Время: метки уже МСК-стенка как UTC, `day_of(ts)`, `minute_of_day(ts)`, `by_day(rows)` без сдвига +3 ч.
- Контроли: `shuffle_within_day(values, days, rng)`, `permute_days(rows_by_day, rng)`, `shift_grid(offset)(minute, g)`; интервал `bootstrap_days(rows_by_day, stat, draws, rng)`; вердикт `pvalue_and_ci(real, nulls, boots)` -> `{stat, p, ci95, n_null}` (p односторонний, «нуль >= настоящего»).
- Справки: `halves(rows)` (по целым дням), `atr_minute(rows)`, `round_trip_cost_pts(symbol, price)` (RI 10 пт по стакану, прочие только комиссия или None).
- Минимальный модуль: чистая `analyze(rows, ...) -> {"rows", "halves", "n_days", "notes"}` (её тестирует синтетика) и тонкая `run(arg: dict)`: `arg = {"symbol_key", "since", "until", <свои оси>, "draws", "seed"}`, `rows = common.load_bars(...)`, затем `return common.report("<ID>", key, [since, until], res["rows"], res["notes"], n_days=..., halves=..., cost_pts=..., atr_min_pts=...)`.
- Исключённые минуты (клиринги, ночь, открытия) считаются в `notes`, не выбрасываются молча. Нуль с одним фиксированным сдвигом даёт p не ниже 1/g: сдвиг разыгрывается по дням (см. a4).
