# Умные заявки для ручной торговли (v1)

Заказ 2026-07-21 (ночь): «функция для моих ручных умных заявок: условная (SL,
TP, Trail TP, Conditional — выставлять заявку если прошла сделка по другой
заявке)».

## Что это

STL-сторонний вотчер (1с цикл внутри процесса STL) над персистентной книгой
умных заявок. Срабатывание = обычная лимитка через ШТАТНЫЙ человеческий путь
`/api/v1/quik/orders/place`-семантики: master-флаг, коллар, капы, kill-switch —
всё действует. Дочерние client_id `so:<id>` — на агенте это MANUAL-класс (без
тега), сверка их не трогает, роботы не видят.

Цены дочерних заявок ВСЕГДА маркетабельны (кросс с подушкой ~0.05%, кап 0.15%
под коллар 0.2%) и КВАНТОВАНЫ к шагу цены инструмента (урок 2026-07-21:
офф-грид цену QUIK молча режет).

## Виды (обзор «что бывает» из практики сообществ: стоп-заявки QUIK, брокерские
bracket/OCO/OSO)

| kind | Что делает | Поля |
|---|---|---|
| `sl` | Стоп-лосс: side=sell сработает при цене <= trigger (защита лонга); side=buy при цене >= trigger (защита шорта) | `trigger_price` |
| `tp` | Тейк-профит: side=sell при цене >= trigger; side=buy при цене <= trigger | `trigger_price` |
| `trail_tp` | Трейлинг-стоп: опц. уровень активации (`trigger_price`, 0 = сразу), дальше тянет пик и стреляет при откате на `trail_offset` ПУНКТОВ | `trail_offset`, опц. `trigger_price` |
| `on_fill` | Условная (OSO, «по исполнению»): дочерняя заявка в момент FILLED наблюдаемого `watch_client_id` | `watch_client_id`, опц. `child_price` (0 = по рынку) |
| OCO-группа | Любые заявки с одинаковым непустым `oco_group`: сработала одна — остальные отменяются (классический bracket SL+TP) | `oco_group` |

Триггер — по LAST сделки (как стоп-заявки QUIK), фолбэк mid(bid/ask). Протухшая
котировка (>30с) НИКОГДА не стреляет. Опц. `good_till_ms` — автопротухание.

Отложено на потом (осознанно): iceberg (скрытый объём), лесенка/scale-in,
активация по времени, стоп по другой бумаге.

## API (portal-auth, как все /api/v1/quik/*)

```bash
# SL на лонг 5 RIU6: продать 5, если last <= 83500
curl -X POST .../api/v1/quik/smart-orders -d '{
  "kind":"sl","code":"RIU6","side":"sell","qty":5,"trigger_price":83500}'

# Bracket: вход + привязанные SL и TP (OCO), всё одной цепочкой:
# 1) обычный вход через /api/v1/quik/orders/place c client_id=op-e1
# 2) on_fill вешает пару после исполнения входа:
curl -X POST .../smart-orders -d '{"kind":"on_fill","code":"RIU6","side":"sell",
  "qty":5,"watch_client_id":"op-e1","child_price":84500}'      # TP-лимитка
curl -X POST .../smart-orders -d '{"kind":"sl","code":"RIU6","side":"sell",
  "qty":5,"trigger_price":83200,"oco_group":"br1"}'
curl -X POST .../smart-orders -d '{"kind":"tp","code":"RIU6","side":"sell",
  "qty":5,"trigger_price":84500,"oco_group":"br1"}'

# Трейлинг: активация с 84000, откат 150 пунктов от пика
curl -X POST .../smart-orders -d '{"kind":"trail_tp","code":"RIU6","side":"sell",
  "qty":5,"trigger_price":84000,"trail_offset":150}'

curl .../api/v1/quik/smart-orders            # список + статусы
curl -X DELETE .../api/v1/quik/smart-orders/<so_id>   # отмена (armed only)
```

Статусы: `armed` → `fired` | `cancelled` (оператор/OCO) | `expired` |
`error` (отклонено лимитами — НЕ перевзводится, причина в `note`).

## Персистентность и рестарты

Книга в `data/smart_orders.json` (атомная запись), грузится в lifespan.
Трейлинг-пик тоже персистится. Рестарт STL заявки переживают.

## Ограничения v1 (честно)

- Вотчер живёт В ПРОЦЕССЕ STL: STL лежит → умные заявки СПЯТ (роботы на агенте
  не затронуты). Для ручных заявок оператора это осознанный компромисс.
- Тик-гранулярность 1с и триггер по change-gated тикам агента: экстремум внутри
  секунды может проскочить мимо трейлинг-пика.
- kill-switch активен → триггеры не стреляют (остаются armed).
- v2 (правильная надёжность): нативные стоп-заявки QUIK (`NEW_STOP_ORDER`:
  SIMPLE_STOP_ORDER / TAKE_PROFIT_STOP_ORDER с отступом / WITH_LINKED_LIMIT /
  ACTIVATED_BY_ORDER) через Lua-мост — сработка на стороне QUIK-сервера,
  переживает всё. Нужны: расширение proto, Go-агент, Lua (рестарт скрипта
  оператором!), поэтому в ночь не делалось.
