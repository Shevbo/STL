# «Меньше сделок, больше прибыли на сделку»: пререгистрация (01.10.2026)

Вопрос оператора: можно ли прокачать живого lxk22 так, чтобы сделок было меньше, а тейк
больше. Критерии записаны ДО прогона и не меняются; отступления фиксируются с причиной.
Данные только 2026. Счёт на i9, вывод после проверки fable. Живые параметры меняет только
real-trade по решению оператора; этот документ ничего в бою не меняет.

## Почему направление верное

Сентябрьский журнал lxk22 (16-29.09): gross +9.0 тыс ₽ на 1 522 лота = 3.5 пт на лот уже после
спреда; комиссия 2.4-4.5 пт на лот (факт QUIK и модель). Преимущество на лот равно издержкам,
робот у нуля. 1 090 филлов в месяц. Каждая убранная сделка с ожиданием ниже издержек = плюс.

## Часть A. Фильтры входа у lxk22 (парные сравнения)

База B = живой `params_json` lxk22 (`scratchpad/exec/touchbt/lxk22_live.json`: fast=57, slow=48,
signal=10, avg_max=20, avg_step_atr=21, k_avg=20, bet_step=2, bet_max=10, super_y=2, super_z=2,
sl_pct=100, tp_atr=80, dv_bars=60, dv_range_pts=300, cooldown_min=0, min_gap_pts=0, tod 600/1080
3/2/1, nd_days=5). Если фактический живой набор на момент прогона отличается, берётся фактический.

Окна по контрактам: W1 RIH6 05.01-14.03, W2 RIM6 16.03-14.06, W3 RIU6 16.06-15.09, W4 RIZ6
16.09-30.09. Исполнение по барам, издержки: комиссия движка плюс спред 10 пт на круг (вычет по
филлам, как в гейте UNI-kelt).

Варианты: меняется ОДНА ось, остальное как в B.

| ось | значения | смысл |
|---|---|---|
| `cost_atr` | 20, 40, 60 | вход только при ATR выше доли цены круга |
| `flip_min_pts` | 200, 400, 800 | разворот только после хода от средней |
| `min_gap_atr` | 10, 20, 30 | разножка между входами |
| `avg_step_atr` | 30, 40 | реже ступени лестницы |
| `cooldown_min` | 5, 15 | остывание после прибыльного выхода |
| `dv_range_pts` | 450, 600 | шире «долина смерти» |
| `tp_atr` | 40, 160 | тейк ближе и дальше (сейчас 8×ATR, фактически без тейка) |

Метрики по каждому окну: net после издержек, число кругов, net на круг, худшая просадка по ВМ
(max_mae).

Критерий «вариант лучше базы» (все пункты):
1. net(вариант) − net(B) > 0 минимум на трёх окнах из четырёх и в сумме;
2. число кругов в сумме меньше, чем у B, не менее чем на 30% (для `tp_atr` пункт не требуется);
3. суммарная худшая просадка по ВМ не хуже базы более чем на 20%;
4. монотонность по оси: соседнее значение той же оси тоже не хуже базы в сумме (защита от
   одиночного пика; для осей из двух значений оба не хуже базы).
Вариантов 17: при четырёх окнах случайное прохождение пункта 1 одним вариантом вероятно,
поэтому прошедший вариант не идёт в бой, а идёт бумажным двойником на агенте (закрытые бары)
минимум на 3 недели и сравнивается с живым попарно по дням.

## Часть B. Медленный супертренд (проверка вне выборки)

Происхождение: в плацебо гейта UNI-kelt (50 случайных трендовых векторов, сид 20261001) три
вектора `supertrend` (номера 5, 8, 11 в `scratchpad/gate/sets/g6_vectors.json`) дали плюс на W1
(RIH6) и W3 (RIU6 15.06-20.08) при 54-70 сделках на окно. Это лучшие из 50 случайных, то есть
отбор по результату; доказательством не является.

Нетронутое окно: W0 = RIU6 21.08-15.09 и RIZ6 16.09-30.09 (в плацебо не входило).
Векторы берутся из файла наборов как есть, без изменений.

Критерии (кандидат на бумажный форвард, только если все):
- B1. На W0 (сумма двух контрактов) net после издержек > 0 минимум у двух векторов из трёх.
- B2. Вектор с лучшим результатом на W1+W3 (номер 5) на W0 в плюсе сам.
- B3. Стороны на W0+W1+W3: «только лонг» и «только шорт» вектора 5 оба >= 0.
- B4. Окрестность вектора 5 (каждый параметр ±20% и ±40%, остальные как у вектора; около 8-12
  соседей) на W1+W2+W3+W0: не менее 60% соседей с суммой > 0.
- B5. Число сделок вектора 5 на всех окнах вместе >= 150.
- B6 (справочно). Тот же вектор на SiH6/SiM6/SiU6/SiZ6 в тех же окнах, спред 1 пт.
Прохождение B1-B5 = бумажный двойник на агенте, не реал.
