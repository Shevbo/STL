# Экран «Прогоны» (LAB-RUNS) — спека v1

Автор: окно backtests (дизайн заказан оператором у fable, 23.09.2026).
Реализация — зона ui-ux (`frontend/`, `trader/api/`). Данные и правда в цифрах — зона backtests.

Задача оператора: он смотрит сделки и кривую доходности вместо чтения отчётов ассистента.

## Требования оператора (дословно)

1. При выборе стратегии — вижу все её прогоны, даты прогона, параметры и финрезы, удобно и быстро.
2. Если показ требует ожидания дольше 10 секунд (выборка из БД или обработка) — сообщается
   пользователю и показывается прогресс-бар.
3. «Системный монитор прогона» — ИИ-ассистент В КОНТЕКСТЕ выбранной стратегии и показанных
   прогонов: спрашиваю про любую деталь на экране, он отвечает по ней.
4. Под системным монитором — область визуализации кривой доходности; ассистент по запросу
   сразу выводит туда нужный график.

Жалобы на текущий экран: ассистент не принимает ввод; прогоны не переключаются при смене
стратегии; лонгрид должен стартовать свёрнутым.

## Ограничения данных (факты, не пожелания)

- Строка `optimization_leaderboard` = один вектор параметров с метриками. 1 258 347 строк
  после чистки 22.09. У `macd_shectory1` 44 параметра в векторе.
- **У строк кампаний НЕТ ни сделок, ни кривой.** API сохраняет `trades`/`equity_curve` только
  у ЛУЧШЕЙ комбинации прогона (комментарий про bloat и nginx 413 в `trader/api/app.py`).
  Проверено: во всех 1626 строках кампаний 22.09 сделки пусты.
- Увидеть сделки строки = досчитать её одиночным прогоном (голый cuid, не `camp-`/`opt-`):
  он хранит полные `trades` и `equity`. Один комбо на 40 днях — секунды; в очереди может стоять
  кампания на часы, ручные прогоны идут вперёд по `priority`.
- **Единицы.** `net_profit` в РУБЛЯХ, если в строке заполнен `point_value`, и в ПУНКТАХ, если он
  пуст (синтетические символы вида `spRIZ6d0921`). Путаница в единицах за сутки дважды дала
  неверный вывод о деньгах. Единица берётся ИЗ СТРОКИ и пишется рядом с каждой суммой.
- Имена кампаний в базе нечитаемы: `camp-20260922-camp20260922reof000`.
- **Свободный поиск подстрокой по `campaign_run` запрещён**: LIKE с ведущим процентом = полный
  скан, такой запрос ронял хостер (LA 31, API отвечал таймаутами). Допустимы префикс, списки,
  фильтры по стратегии и символу.
- Индексы на 23.09: `pkey`, `idx_lb_score`, `idx_lb_candidate`, `idx_lb_created_at`,
  `idx_lb_strategy_symbol_score (strategy, symbol, score DESC)`,
  `idx_lb_campaign_run_net (campaign_run, net_profit DESC)`. Для «прогоны стратегии по дате»
  ни один не покрывает сортировку: нужен `(strategy, created_at DESC)`, ставить CONCURRENTLY.

                  | символ v  кампания v  окно от/до  [сбросить]   N строк
                  | дата | кампания | символ | окно | финрез+ед. | сделок | MAE | RF
                  | > развёрнутая строка: все 44 параметра сеткой (ParamPanel)
                  | высота до 45vh, свой скролл, строки сворачиваемые
                  |----------------------------+--------------------------------

                  | метрики крупно + единица   |--------------------------------
                  | параметры (ParamPanel)     | ГРАФИК (>=260px, тянется до низа)
                  | [Досчитать · ~25 с]        | кривая / сделки / просадка

Монитор и график — вертикальная пара (требование 4). Описание стратегии — строка
«описание v» под заголовком, ВСЕГДА свёрнута на старте, развёрнутое состояние не запоминать.
Убрать CRT-декор (скан-линия, мигающий курсор) и emoji в заголовках.

### Таблица прогонов

Колонки v1: дата (`дд.мм чч:мм`) · кампания (метка) · символ · окно · финрез с единицей ·
сделок · просадка · MAE · RF · параметры (свёрнуто 3 ключевых, развёрнуто все) · действие.

- Единица в каждой ячейке: рубли, если `point_value` заполнен, иначе пункты. Не из выбранного
  символа, не из множителя по умолчанию. В CSV отдельная колонка `unit`. MAE и просадка — той же
  единицей, что финрез.
- Метка кампании: снять префикс `camp-`/`opt-`, дату `YYYYMMDD` в `дд.мм`, снять повтор
  `camp<дата>` из хвоста. `camp-20260922-camp20260922reof000` в `22.09 reof000`.
  Полный id в `title`, копируется по клику.
- Страница 200 строк и кнопка «ещё 200» по курсору `created_at`. Без бесконечного скролла.
- Клик по строке = выбрать (панель и график). Клик по стрелке = развернуть параметры;
  значения, отличные от `default_params`, подсвечены.

### Фильтры

Стратегия — список слева (каталог в памяти, БД не трогаем). Символ и кампания — выпадающие,
значения с сервера (`DISTINCT ... WHERE strategy=$1`, у кампании число строк и дата).
Окно — два поля типа date. Ни одного текстового поля, уходящего в БД.

## Смена стратегии (починка бага «прогоны не переключаются»)

Один источник истины `selectedStrategyId`, остальное производное. Корень текущего бага:
`loadRobotRuns()` вызывается только из эффекта дип-линка `?hist=` с гардом `!robotRunsFor`,
а `selectStrategy()` список прогонов не трогает.

1. `seq++`; ответ с чужим `seq` игнорируется.
2. Сброс: выбранная строка, панель, график (скрыть, не оставлять чужую кривую), фильтры в «все»,
   страница в первую.
3. Монитор: лента очищается, первая строка «контекст: <стратегия> · загружаю прогоны», ввод
   заблокирован с причиной в placeholder.
4. Параллельно `GET /api/v1/lab/runs?strategy=...` и `GET /api/v1/lab/run-facets?strategy=...`.
5. Автовыбор самой свежей строки, ввод монитора разблокирован.
6. URL `?runs=<strategy>&symbol=...&campaign=...` синхронно со стейтом; дип-линк `?hist=` ведёт
   сюда же.

Идёт дорасчёт, а стратегию сменили: опрос продолжается, результат в кэш по `run_id`, на экран не
выводится; при возврате строка «прогон <id> готов, стратегия сменена».

### Состояние «сделок нет, нужен дорасчёт»

1. Строка выбрана — фоновый запрос «есть ли сохранённые сделки этого вектора»: обобщить
   существующий `campaign-result` (сопоставление params в `backtest_results`) в
   `GET /api/v1/lab/row-trades?strategy&symbol&date_from&date_to&params=<json>`.
2. Не нашлось — одна плашка в панели и в области графика: «Хранятся только метрики. Сделки и
   кривая считаются заново на i9» и кнопка **«Досчитать · ~25 с»**. Стоимость живая из
   `GET /api/v1/lab/queue-estimate`: `{i9_alive, typical_sec, manual_ahead, cur_remain_sec}`.
3. Нажатие — `POST /api/v1/backtest/run`, приоритет ручной, `param_sets` из одного вектора,
   `engine: remote`, окно дат и символ ИЗ СТРОКИ (не из выбора слева — иначе кривая врёт на
   миллионы, это уже было). Опрос `/status` раз в 2 с. «Отменить» пока статус queued.
4. Готово — `results?full=1`, график, `run_id` привязан к строке; повторный выбор мгновенный.
5. **Авто-дорасчёт по клику запрещён**: текущий `openRun()` сам делает `rerunFromChart`, двадцать
   кликов равны двадцати заданиям i9. Только явная кнопка или явная команда ассистенту.

## Ассистент (требование 3)

Компонент `RobotConsole` с `onAsk` (рабочий ввод там уже есть). Enter отправляет, Esc очищает,
слэш фокусирует, disabled пока ждём. Ответ не длиннее 6 строк, числа с единицей и ссылкой на
строку. Эндпоинт `POST /api/v1/lab/chat` `{message, context, history}` в `{type, text, actions}`,
по образцу `trader/api/quik_robot_chat.py`, LLM только через Lineman.

Контекст (клиент собирает из того, что на экране, при каждом вопросе):
`screen`, `strategy {id, name, description_short, params_schema[{key,label,unit,default}]}`,
`filters`, `runs_visible` (до 50, как на экране), `selected` (все 44 параметра, `run_id` или
null), `trades_summary` и `last_trades` (до 50) если загружены, `equity` (до 200 точек, `peak`,
`max_dd`), `queue {i9_alive, typical_sec, manual_ahead}`, `chart {row_key, kind}`, `history` (до
10). Все сделки целиком не слать.

Действия в ответе: `{"chart":{"row","kind":"equity|trades|drawdown"}}`, `{"select_row":key}`,
`{"recalc":key}` (только если пользователь явно просил досчитать). Неизвестное действие
игнорируется и логируется. Нет сделок — тип `insufficient` и подсветка кнопки «Досчитать»,
рисовать нечего.

Разрешённые типы ответа (enum, сервер валидирует): `fact`, `compare` (только числа из контекста,
арифметика сумма/разность/среднее, показывать формулу), `explain_param` (из `params_schema`,
в единицах инструмента), `chart`, `status`, `howto`, `insufficient`.

**Запрещено и кодируется на сервере:** оценка стратегии по строкам лидерборда — «хорошая»,
«рабочая», «есть преимущество», «эдж», «рекомендую», «можно торговать», прогноз дохода. Причина:
одна строка лидерборда это подгонка, на этом сгорели недели. Слово «лучшая» только с уточнением
«по <метрике> на этом окне» и с числом сделок. Числа, которых нет в контексте. Всё про живых
роботов и арминг — `insufficient` с отсылкой на стенд робота.

Проверка после ответа: регулярка по корням «хорош», «рабоч», «эдж», «преимуществ», «рекоменд»,
«стоит запуст», «можно торгов», «прибыльная стратегия», «будет зарабат»; совпало при типе, не
равном `insufficient` — текст заменяется фиксированной строкой: «Оценка стратегии по строкам
лидерборда запрещена: одна строка = подгонка. Нужен гейт: второй контракт, зеркало сторон, порог
сделок, вычет спреда, оптимум не на краю сетки». Замена логируется. Юнит-тест: вопрос «стратегия
хорошая?» даёт ровно эту строку.

## Приоритеты

**Итерация 1 (польза в первый день):** индекс `(strategy, created_at DESC)` CONCURRENTLY;
`GET /api/v1/lab/runs`, `run-facets`, `queue-estimate`; таблица с единицей из строки, метками
кампаний, фильтрами-списками, CSV, сворачиваемыми параметрами; смена стратегии со сбросом и
гардом по `seq`; выбор строки в панель, кнопка «Досчитать» с очередью и ETA, график из
результата; монитор на `RobotConsole` с рабочим вводом, `POST /api/v1/lab/chat`, enum типов и
серверный фильтр запретов; лонгрид свёрнут, декор снят.

**Итерация 2:** действия `chart`, `select_row`, `recalc`, вид `drawdown`; `row-trades` для
мгновенного открытия уже досчитанных строк; список сделок под графиком (сворачиваемые строки,
CSV); запуск с изменёнными параметрами из ParamPanel; подсветка отличий от дефолтов.

**Итерация 3:** наложение двух кривых; `trades_summary` и `equity` в контексте ассистента; объект
`gate` из гейта кандидатов в контексте — единственный путь к ответам-оценкам.

## Что даёт backtests

По запросу ui-ux: функция «строка лидерборда в готовый вектор параметров для одиночного
прогона»; словарь человеческих подсказок по параметрам (он уже есть в
`trader/lab/strategies/library.py`, для каждого ключа с объяснением, зачем ось заведена и чем
кусается) — ассистент обязан цитировать его, а не выдумывать; список кампаний с человеческими
названиями.
