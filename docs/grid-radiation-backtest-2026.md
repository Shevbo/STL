# Бэктест умной заявки «радиация» (сетка): пререгистрация (01.10.2026)

Заказ оператора: бэктест «радиации» с параметрами, варианты, которые в плюсе на разных периодах,
и анализ рынка, когда она теряет. Механика берётся ровно из `trader/quik/smart_orders.py`
(`grid_levels`, `grid_price`, `grid_side_for`, `grid_consumed`, `grid_stop_levels`) и памяти
`project_grid_radiation_spec`: фиксированные уровни base ± k·step (база тоже уровень), выше рынка
продажа, ниже покупка, филл гасит свой уровень и возвращает погашенных соседей ±1, стоп за
последним уровнем на `g_stop_pts` закрывает позицию и завершает сетку. Тейка нет.
Данные только 2026, счёт на i9, вывод после проверки fable. Код STL не трогается: симулятор
импортирует функции уровней из `smart_orders.py` (одна семантика с боем).

## Симуляция

- Бары M1 контрактов RI (RIH6, RIM6, RIU6, RIZ6), Si (справочно).
- Лимит на уровне L исполняется, если бар прошёл L не меньше чем на `fill_pen` шагов цены (1),
  по цене L. Путь внутри бара: если close >= open, open → low → high → close, иначе
  open → high → low → close; на каждом отрезке уровни исполняются по порядку прохождения, гашение
  и возврат соседей применяются сразу (уровень, возвращённый внутри отрезка, может исполниться на
  следующем отрезке, но не на том же).
- Стоп: close бара за уровнем стопа, выход всей позиции по open следующего бара плюс полспреда
  (RI 5 пт). Справочно `stop_mode=1`: по уровню стопа при касании.
- Перезапуск: сетка ставится в начале каждого торгового дня в 10:00 (база = open бара 10:00), живёт
  до стопа или до 23:40, в 23:40 позиция закрывается по close бара (политика «без ночёвок»).
  Справочно режим `restart=after_stop`: после стопа новая сетка от цены следующего бара в тот же
  день. Лимитные заявки не пересекают рынок (правило `grid_side_for`).
- Издержки: две границы комиссии: мейкер (только брокер 0.45 ₽ за контракт) и тейкер (биржа +
  брокер по `commission.py`, без скидок); лимитные филлы без спреда.

## Сетка параметров (RI)

| параметр | значения |
|---|---|
| `g_step` (пт) | 50, 100, 150, 200, 300, 400, 600 |
| `g_buys` = `g_sells` | 2, 3, 5, 8, 12 |
| `g_stop_pts` (пт, 0 = без стопа) | 0, 100, 300, 600, 1000 |
| `g_lot` | 1 |
| асимметрия: `g_buys`/`g_sells` | дополнительно (5,2), (2,5), (8,3), (3,8) при шаге 100, 200, 300 |

## Периоды и критерии

Периоды: 13 четырёхнедельных блоков с января по сентябрь 2026 (по контракту, без склейки).
- R1. Вариант «в плюсе на разных периодах»: net (обе границы комиссии отдельно) > 0 минимум в
  70% блоков и в сумме, худший блок не хуже −3× медианного блока по модулю.
- R2. Окрестность: соседние варианты (шаг по каждой оси) тоже проходят R1 хотя бы в 60%.
- R3. Отдельно отчитать варианты, проходящие R1 только с мейкерской комиссией (их судьба зависит
  от фактической комиссии из QUIK).

## Анализ «когда теряет»

По каждому дню для лучших 5 вариантов и для живого набора параметров оператора: дневной net и
описатели дня: ход дня |close−open| в ATR дня, направленность (|close−open| / (high−low)),
размах в ATR, число пересечений базы, был ли стоп, время стопа, событийные минуты (10:00, 17:00),
день недели. Таблицы: net по квинтилям направленности и размаха; доля убыточных дней с выходом
цены за последний уровень; топ-20 худших дней с описателями. Ожидаемая форма (проверяется, а не
принимается): сетка зарабатывает в боковике и теряет в направленном движении; задача найти
порог направленности, выше которого день убыточен, и есть ли признак, видимый в первые 30-60
минут дня (тогда это фильтр запуска сетки, который проверяется отдельно на последней трети данных).
