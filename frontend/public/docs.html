Документация платформы STL

Shectory Trade & Lab — торговая платформа FORTS: живая торговля через QUIK, бумажные роботы, бэктест и перебор параметров, ручные заявки со сторожем.

1. Требования#

Что платформа обязана делать. Сгруппировано по областям, каждый пункт с номером.

Живая торговля#

  • Т-1Роботы на реальные деньги торгуют НЕ в процессе STL, а на QUIK-агенте (Windows VDS рядом с терминалом QUIK). Падение STL не останавливает торговлю — агент дозванивается сам и продолжает вести открытые позиции.
  • Т-2Ордера идут в QUIK через QLua-мост (файловая очередь, не LuaSocket). Робот-ордера всегда маркетабельны (BUY по аску / SELL по биду) и квантованы на шаг цены инструмента — иначе заявка отклоняется биржей и не исполняется никогда.
  • Т-3Торговля включается ДВУМЯ независимыми флагами разом: `quik_trading_enabled` на стороне STL и локальный флаг в `agent_config.json` на агенте. STL не может удалённо взвести флаг агента.
  • Т-4Иммунитет к рестартам: закрытые бары и состояние робота персистятся на агенте (`runner_state.json`), исторический бар не переисполняется повторно после любого перезапуска.

Бумажная торговля и Lab#

  • Т-5Paper-роботы живут в Postgres (таблица robots) и исполняются планировщиком STL (`trader/lab/scheduler.py`).
  • Т-6Один и тот же протокол исполнения (`STLRuntime`) обслуживает бэктест, paper-робота в STL и live-робота на агенте — одна и та же стратегия ведёт себя идентично во всех трёх режимах.

Бэктест и переборы параметров#

  • Т-7Никакие тяжёлые вычисления (свипы параметров, переборы) не выполняются в процессе STL API — они уходят на выносные агенты (i9, VDS-фолбэк), чтобы не блокировать событийный цикл и не ронять живую торговлю.
  • Т-8Результаты сводятся в единый хитпарад (Ботстор / `optimization_leaderboard`) независимо от того, какой агент считал.

Честный учёт денег#

  • Т-9Пофилловый журнал algo_trades — каждая сделка учтена отдельно, gross/net с комиссией.
  • Т-10P&L робота на раннере считается в ЦЕНОВЫХ ПУНКТАХ, а не в рублях; перевод в рубли делает UI через коэффициент step_cost / price_step инструмента. Точку и рубль путать нельзя — коэффициент чужого инструмента даёт результат, отличающийся в сотни раз.

Защита от ложных данных#

  • Т-11После рестарта QUIK лента сделок какое-то время реплеит уже прошедший день — бары становятся стухшими при живых котировках. Реальные роботы должны автоматически ставиться на паузу, пока задержка биржи (`exchange_lag_ms`) не станет нормальной.
  • Т-12Оракул торговой сессии MOEX (`trader/market_session.py`) отличает «биржа закрыта» от «лента умерла при открытой бирже» по факту SYSTIME ISS, а не по зашитому в код календарю (расписание меняется, праздники и торги выходного дня меняются).

Наблюдаемость#

  • Т-13Вотчер прогоняет проверки каждые 10 минут в торговое окно (06:55–23:55 МСК), логирует найденное и умеет эскалировать критичные случаи по SMS.
  • Т-14Компаньон в трее Windows даёт оператору счёт, позиции, роботов и здоровье STL без открытия браузера, токен только на чтение.

Ручные заявки#

  • Т-15Оператор может выставлять обычные лимитные заявки и «умные» заявки (SL/TP/трейлинг/по исполнению/OCO) со сторожем, который следит за ценой и сам ставит дочернюю заявку при срабатывании.
  • Т-16Умная заявка никогда не стреляет по неактуальной цене (стухший тик) и всегда квантуется на шаг цены при выставлении.

STL backend + frontend#

Python 3.12 / FastAPI / asyncio, хостится на Ubuntu-сервере (`shectory-trader.service`, uvicorn :8000). Контрольная плоскость + монитор + исполнение через Finam Trade API (HTTP/2), хостинг Lab-фреймворка стратегий и бэктестера. Никакие тяжёлые вычисления не выполняются внутри — см. Т-7. Фронтенд — Svelte 5 SPA (lightweight-charts + uplot), статика через nginx, `/api` и `/ws` проксируются на uvicorn. Обновление: сборка фронтенда локально + git push + scp хешированных бандлов, сервис бэкенда рестартуется только при изменении Python-кода (раздел 4).

QUIK-агент#

Go single-exe на Windows VDS рядом с терминалом QUIK. Дозванивается до STL по одному живому bidi gRPC-стриму (на Windows нет входящего порта). Рыночные данные приходят из QLua-паблишера через файловую очередь (тики, книга L2, обезличенная лента всех сделок, параметры инструмента); заявки идут через тот же Lua-мост. Хостит живых роботов (см. ниже). Самообновляется: применяет новый релиз на старте, в 03:00 МСК, либо по явной команде из STL; апдейт — zip, который апдейт-скрипт агента разворачивает поверх текущей установки.

Robot runner#

Python, собран в единый robot-runner.exe (PyInstaller), упакован ВНУТРЬ релизного zip агента. Исполняет стратегии `trader/lab` 1:1 (тот же протокол `STLRuntime`) против локальных данных QUIK через loopback-мост агента (127.0.0.1:50071). Персистит роботов и состояние рядом с агентом, зеро-тач резюм после любого рестарта — агент реплеит сохранённые спеки роботов при каждом переподключении раннера. Обновляется вместе с агентом (тот же zip, тот же апдейт-цикл 03:00).

Опт-агент i9#

Отдельная машина (Win10-HyperV, копия репозитория БЕЗ git — синхронизация вручную или через манифест самообновления агента) забирает джобы перебора параметров через /api/v1/agent/claim по HTTPS и считает бэктесты пачками комбинаций. Результаты уходят в backtest_results, кампании с префиксом camp-/opt- дополнительно зеркалятся в optimization_leaderboard (Ботстор). Обновляется по манифесту agent/update_manifest.txt самостоятельно.

Компаньон#

STLCompanion.exe — трей-панель Windows, read-only. WebView2 без рамки, вёрстка приезжает с STL (companion.html), exe отвечает только за окно/трей/токен/локальный прокси. Токен на чтение выдаётся один раз по короткоживущему коду сопряжения (15 минут, одноразовый) и хранится через DPAPI под учётной записью Windows — пароль не запрашивается никогда. Доставляется скачиванием exe оператором вручную (не самообновляется как агент).

Два wire-контракта#

Центр тяжести обмена данными — два protobuf-контракта в proto/shectory/quik/v1/:

quik_agent.protoагент↔STL стрим. Агент → STL: Register/Heartbeat/тики/книги/OrderUpdate/TransReply/LimitsState/RobotStatusReport. STL → агент: Ack/PlaceOrder/CancelOrder/ReplaceOrder/KillSwitch/SetLimits/DeployRobot/UndeployRobot/SetRobotParams/PauseRobot/StartRobot.
runner_bridge.protoloopback агент↔раннер: StreamTicks/StreamTape/StreamControl/StreamOrderEvents/PlaceRunnerOrder/ReportStatus.

Оба контракта регенерируются вместе (make gen) при любой правке любого из proto-файлов.

Файловая очередь Lua#

DDE-сервер отключён по умолчанию (легаси, включается только `SHECTORY_ENABLE_DDE=1`). Рыночные данные и заявки ходят через файловую очередь скрипта shectory_trade.lua, живущего в ПАМЯТИ терминала QUIK: тики (500 мс), книга L2 (1 c, только пока в терминале открыто окно стакана по инструменту), обезличенная лента всех сделок (батчи по 300 мс, требует открытого окна «Таблица всех сделок»), параметры инструмента (шаг цены/стоимость шага/ГО, раз в 60 c). Заявки идут через sendTransaction того же скрипта. Копия файла на диске не значит, что код в терминале обновился — скрипт нужно перезапустить руками через Сервисы → Lua-скрипты.

Dual trading safety#

Заявка в QUIK требует, чтобы мастер-флаг торговли был включён С ОБЕИХ сторон разом: в STL (`quik_trading_enabled`) и локально в `agent_config.json` на агенте. STL никогда не взводит флаг агента удалённо — она может только толкать вайтлист инструментов и числовые лимиты через SetLimits при подключении, агент эхает свои действующие лимиты обратно через LimitsState. Эффективный лимит — минимум из бэкстопа агента и пуша STL; агент только УЖЕСТОЧАЕТ лимит на лету, более широкие значения перечитывает только при старте.

Маркетабельные цены и шаг цены#

Робот-ордера идут маркетабельно (SELL по биду / BUY по аску от свежей котировки, крест шире при стухшей котировке), а не через движок-мейкер ручных заявок. Цена ОБЯЗАНА быть кратна шагу цены инструмента — квантование делает АГЕНТ, потому что только он знает `PriceStep` из параметров QLua; раннер шага не знает. Заявка не на сетке шага отклоняется биржей («не кратно шагу») и не исполняется никогда, а робот переотправляет её на каждом баре — позиция зависает без исполнения.

3. Инструкции пользователя#

По экранам платформы. Бургер-меню (☰) стоит на каждом экране и открывает карту всего сайта.
Терминал (главный экран)#

Стартовый экран (/). Три ключевые панели:

  • Стакан — книга заявок по выбранному инструменту, обновляется в реальном времени.
  • Тикет — форма выставления заявки: инструмент, сторона, количество, цена.
  • Позиции — открытые позиции по счёту с текущим P&L.

Отсюда же доступен бургер-меню со ссылками на все остальные экраны платформы.

Заявки: обычная / умные / графики#

Экран /?orders=1, три вкладки:

  1. Обычная заявка — классический лимитный ордер: инструмент, сторона, количество, цена.
  2. Умные заявки — заявка со сторожем. Вкладка держит счётчик взведённых прямо на корешке, чтобы было видно даже когда открыта другая вкладка — умная заявка сработает без вашего участия.
  3. Позиции и заявки на графиках — те же данные визуально, поверх ценового графика.

Типы умных заявок

ТипЧто делает
Стоп-лосс (SL)Ограничивает убыток. Сторож раз в секунду смотрит цену последней сделки; для продажи срабатывает, когда цена опустилась до стоп-цены или ниже (защита лонга), для покупки — когда поднялась до уровня или выше (защита шорта). В момент срабатывания ставится маркетабельная лимитка.
Тейк-профит (TP)Фиксирует прибыль на заранее назначенной цене — зеркально стоп-лоссу по направлению срабатывания.
Скользящий стоп (Trail)Пока цена не дошла до уровня активации (0 = следить сразу), заявка спит. После активации сторож запоминает лучшую достигнутую цену (пик для продажи / дно для покупки) и подтягивает её за движением, никогда не откатывая назад. Срабатывает, когда цена отошла от пика на заданный отступ в пунктах.
По исполнению (on_fill)Заявка-на-заявку: сторож следит за client_id другого ордера и в момент его исполнения ставит дочернюю заявку (например защиту сразу после входа). Цена дочерней заявки — указанная явно, либо по рынку.
Связка OCOЛюбые заявки с одинаковой непустой группой отменяют друг друга при срабатывании одной — классическая пара SL+TP.

Взвод в два клика: сначала показывается фраза «что произойдёт» (условие срабатывания человеческим языком), потом кнопка подтверждения. Дочерние заявки всегда квантуются на шаг цены и никогда не стреляют по стухшему тику (старше 30 с).

Умная заявка живёт внутри процесса STL и переживает его перезапуск (файл на диске), но следящий цикл работает только пока STL запущен — в отличие от роботов на агенте.

LIVE роботы и витрина робота#

Экран /?lab=live — список роботов (paper в STL и live на агенте вперемешку). Открытие робота ведёт на его персональную витрину (/?agent_robot=<robot_id> для агентских).

Что показывает витрина

  • P&L — пожизненный реализованный результат раннера (realized_pnl в пунктах × ₽/пункт инструмента), НЕ результат перерисовки графика по журналу сделок.
  • P&L + Маржа — тот же реализованный результат плюс то, что получится, если закрыть открытую позицию по рынку прямо сейчас (за вычетом комиссии выхода). Показывает «что будет, если зафиксировать всё немедленно».
  • Пауза — блокирует новые входы БЕЗ закрытия позиции: открытая позиция остаётся как есть, работающие заявки снимаются.
  • «Сигнал сейчас» — интроспекция стратегии (что бы она сделала на этом баре). Для standalone-модулей (донгиан, EMA/RSI-кроссовер и др.) может показывать «стратегия не найдена» — это косметика: сама торговля продолжает идти штатно, просто у этого типа стратегий нет разбора сигнала для панели.

Форма кривой на графике идёт из журнала сделок, а конец кривой (последняя точка) смещён на пожизненный realized_pnl раннера — смещением, а не масштабом. Журнал «с флэта» не значит полную историю робота.

Ботстор (хитпарад)#

Экран /?lab=botstore — таблица лучших комбинаций стратегия+инструмент+параметры по итогам переборов на i9 и VDS-фолбэке. Клик по строке пересчитывает и открывает график с реальными сделками и P&L.

Как читать хитпарад: верхняя строка по чистому результату (net) — не единственный ориентир. У сортировки по колонке доступен Win% (доля прибыльных сделок). Долю прибыльных сделок и медианный результат по соседним комбинациям параметров стоит смотреть вместе с вершиной, а не вместо неё: одна аномально удачная комбинация на вершине рейтинга — типичный survivorship bias перебора (из тысяч комбинаций одна всегда окажется лучшей случайно). Устойчивая стратегия — та, у которой соседние по параметрам комбинации тоже прибыльны, а не только сам рекордсмен.

Контр-стратегии (фейд базового сигнала) видны в списке с пометкой «(контр)» у имени — это тот же индикатор, но с инвертированным сигналом входа (суффикс __inv, раздел 5).

Бэктест#

Экран /?lab=backtest — ручной прогон одной стратегии на выбранном инструменте и периоде без постановки в очередь переборщика. Годится, чтобы быстро проверить одну гипотезу или один набор параметров перед тем, как отправлять его в перебор.

Доходность алготорговли#

Экран /?equity=1 — глобальный график доходности по журналу algo_trades: пофилловый учёт всей алготорговли (paper и live вместе), gross/net с комиссией. Это единственное место, где видна СУММАРНАЯ доходность по всем роботам разом, а не по одному роботу.

Компаньон (веб-версия панели)#

Страница /companion.html — та же вёрстка, что показывает трей-приложение STLCompanion.exe на Windows, только в браузере. Сопряжение по короткому коду, который выдаётся на странице вотчера (раздел 4): счёт, позиции, роботы, здоровье STL, эскалации — всё read-only.

Навигация: бургер-меню#

Значок ☰ в шапке любого экрана открывает карту сайта, сгруппированную по смыслу:

4. Администрирование#

Деплой, вотчер, компаньоны, лимиты, операторские зоны, восстановление.
Деплой#

Безопасный деплой (по умолчанию): фронтенд собирается ЛОКАЛЬНО (node ./node_modules/vite/bin/vite.js build), затем git push → ssh hoster git pull → scp хешированных index.html и новых assets/index-*.js/.css в ~/apps/shectory-trader/frontend/dist/. Сборка фронтенда только фронтенд-изменением — сервис НЕ рестартуется, nginx раздаёт статику напрямую. Бэкенд-изменение требует sudo systemctl restart shectory-trader (кратко роняет gRPC-линк с агентом, он передозвонится сам) — никогда не рестартовать во время живого теста торговли оператором.

QUIK-агент + раннер: изменённые Go-файлы и proto скопом (scp) в ~/quik_build на хостере, затем publish_quik_agent.sh [agent_id]. Раннер собирается на Windows (PyInstaller не кросс-компилирует) отдельно и укладывается в ~/quik_build/quik_agent/dist/ до публикации. С agent_id обновление применяется немедленно, без него — в окне самообновления 03:00 МСК без лишнего рестарта живых роботов.

Перед публикацией агента сверять sha256 собранного раннера с эталоном и проверять запись в опубликованном zip — оборванный scp однажды оставил правильный РАЗМЕР файла при неверных байтах, и три публикации подряд ушли с битым архивом.

Вотчер#

Страница /watchdog-log.html. Активации проверок каждые 10 минут в окне 06:55–23:55 МСК. Настройки:

  • Эскалация по SMS — список событий, для каждого включается/выключается отправка SMS; выключенное событие всё равно остаётся в логе с пометкой, просто без SMS.
  • Критические случаи (авто-действия) — переключатели авто-паузы: при отставании тейпа (реплей после рестарта QUIK) и при расхождении баров робота с рынком. Пауза блокирует только новые ордера, позиции не трогаются; утренний авто-резюм снимает ТОЛЬКО паузы, поставленные вотчером.
  • Пороги проверок — числовые границы срабатывания для каждой проверки.
Компаньоны#

Там же, на /watchdog-log.html, блок «Компаньоны»: вводится учётная запись Windows (например WIN10-HYPERV\admin), выдаётся код сопряжения — действует 15 минут, срабатывает один раз. Код вводится в приложении STLCompanion.exe на стороне пользователя, после чего у него read-only токен, зашифрованный DPAPI под его же учётку. Список выданных устройств тут же, у каждого кнопка «Отозвать».

Лимиты#

Дневной кап заявок (quik_daily_order_cap, по умолчанию 500) и капы контрактов на заявку / в работе действуют с ОБЕИХ сторон (STL push + бэкстоп агента), эффективное значение — минимум из двух. Правило поднятия капов: сначала переменные окружения STL (QUIK_MAX_CONTRACTS_PER_ORDER / QUIK_MAX_WORKING_CONTRACTS) + рестарт STL, ПОТОМ рестарт агента — обратный порядок оставляет старые тесные капы в силе. Робот-разворот занимает working-бюджет вдвойне (закрыть N + открыть N = 2N контрактов одновременно) — working-кап должен быть минимум ×2 от per-order.

Операторские зоны#

Часть действий доступна ТОЛЬКО с локальной консоли VDS, никогда удалённо через STL:

  • Перезапуск Lua-скрипта в QUIK (Сервисы → Lua-скрипты) — копия файла на диске не значит, что бегущий код обновился.
  • Арминг робота в реал (переключатель paper/real) — существует только на агенте, требует, чтобы робот был плоским (позиция 0, нет работающих/в полёте заявок, статус известен) и ввода ID робота вручную для подтверждения.
  • Перед ЛЮБЫМ ручным обслуживанием Lua/терминала — выставить quik_guard_disabled: true (или остановить агент), иначе вотчдог vdsguard перезапустит QUIK посреди обслуживания.
Восстановление#
  • Реплей тейпа — после рестарта QUIK лента какое-то время повторяет прошедший день; авто-пауза реальных роботов держится, пока exchange_lag_ms не опустится до нормы.
  • Оракул сессии MOEX — читает поле SYSTIME из ISS по нескольким инструментам сразу и берёт самое свежее; одна сетевая ошибка не должна разблокировать ложную тревогу, при полном провале запроса статус «неизвестно», а не «закрыто».
  • Журнал auto-heal — агент раз в 60 c сверяет сделки QUIK, помеченные тегом робота, с тем, что раннер считает своей книгой, и синтезирует пропущенный филл обратно через обычный событийный путь (идемпотентно, по client_id). Факт QUIK всегда старше убеждения агента.

5. Приложения: стратегии торговли#

Полный каталог из trader/lab/strategies/library.py (реестр индикаторных стратегий, 17 штук) и отдельных модулей trader/lab/strategies/*.py (5 standalone). Реестровые стратегии проходят через общий make_on_bar и автоматически получают универсальные модификаторы позиции (усреднение, тейк, стоп-лосс, разножка, остывание, «долина смерти», ставки, суперусреднение — см. последний блок). Standalone-модули имеют собственный протокол on_bar/on_start/on_stop и модификаторы реестра НЕ наследуют.

Трендследящие#

Пересечения средних, импульс, каналы ATR (8 стратегий)#

MACD Crossover реестр macd_cross

MACD = быстрая EMA минус медленная EMA, сигнальная линия — EMA от MACD. MACD выше сигнальной — держим лонг, ниже — шорт. Всегда в рынке после прогрева, переворот на каждом пересечении.
  • fast 12; 3–30 — период быстрой EMA
  • slow 26; 10–60 — период медленной EMA
  • signal 9; 3–30 — период сигнальной линии
  • qty 1; 1–10 — контрактов на сделку

Shectory-2EMA реестр shectory_2ema

Две EMA, быстрая выше медленной — лонг, ниже — шорт. Всегда в рынке. Встроена система ставок: объём растёт после убыточной сделки и сбрасывается после прибыльной.
  • ema1 10; 3–60 — быстрая EMA
  • ema2 140; 20–400 — медленная EMA
  • qty 1; 1–20 — базовый объём
  • bet_step 1; 0–5 — добавка контрактов после убытка (0=выкл)
  • bet_max 10; 1–30 — потолок добавки по ставкам

Triple SMA Alignment реестр triple_sma

Три SMA разного периода. Все три выстроились по возрастанию — лонг, по убыванию — шорт, перемешаны — выходим в плоскую позицию. Жёсткий фильтр, мало сделок.
  • fast 5; 2–30
  • mid 20; 10–60
  • slow 50; 30–200
  • qty 1; 1–10

EMA Trend + ATR Filter реестр ema_atr

Пересечение двух EMA плюс подтверждение импульсом: цена должна оторваться от медленной EMA на mult×ATR в сторону тренда. Без ATR-подтверждения вход не идёт даже при пересечении EMA.
  • fast 9; 3–40
  • slow 30; 15–120
  • atr_period 14; 5–40
  • mult 5; 1–30 — множитель ATR ×10
  • qty 1; 1–10

Momentum реестр momentum

Моментум = цена сейчас минус цена period баров назад. Положительный — лонг, отрицательный — шорт. Простейший тренд-фолловер.
  • period 10; 2–60
  • qty 1; 1–10

Rate of Change реестр roc

Момент в процентах с порогом фильтрации слабых движений — отличие от Momentum. Выше порога — лонг, ниже минус порога — шорт, внутри — держим что есть.
  • period 12; 2–60
  • threshold 50; 5–300 — порог %×100 (50=0.5%)
  • qty 1; 1–10

EMA Crossover модуль ema_crossover

Эталонный standalone-кроссовер двух EMA на TF=5. Пересечение снизу вверх — лонг фиксированным объёмом 1 контракт, сверху вниз — закрытие лонга. Не переворачивает в шорт.
  • fast_period 9; 2–50
  • slow_period 21; 5–200

SuperTrend (ATR) модуль supertrend

Классический индикатор SuperTrend (Olivier Seban). Полосы = базовая линия (H+L)/2 предыдущего бара ± mult×ATR. Пробой верхней полосы вверх — переворот в лонг, пробой нижней вниз — в шорт. Состояние тренда персистится между барами, повторных входов на каждом баре нет. Публикует плановые уровни переворота (пунктирная линия на графике робота).
  • atr_period 10; 5–50
  • multiplier 30; 10–60 — ширина полос ×10 (30=3.0×ATR)
  • qty 1; 1–10

Контртрендовые

Возврат к среднему, перекупленность/перепроданность (7 стратегий)#

Bollinger Mean-Reversion реестр bollinger_mr

Полоса Боллинджера: SMA(period) ± mult×σ. Цена ниже нижней полосы — «перепродано», покупаем; выше верхней — «перекуплено», продаём; внутри — выходим в плоскую позицию.
  • period 20; 5–60
  • mult 20; 10–40 — сигма ×10 (20=2.0σ)
  • qty 1; 1–10

Stochastic Oscillator реестр stochastic

%K — положение цены в диапазоне high-low за period баров. Ниже уровня перепроданности — лонг, выше перекупленности — шорт.
  • period 14; 5–40
  • oversold 20; 5–40
  • overbought 80; 60–95
  • qty 1; 1–10

CCI Reversal реестр cci

Commodity Channel Index — не ограничен 0–100 как RSI/Stochastic, может показывать более сильные выбросы. Ниже −threshold — лонг, выше +threshold — шорт.
  • period 20; 5–50
  • threshold 100; 50–200
  • qty 1; 1–10

Williams %R реестр williams_r

Аналог Stochastic, перевёрнутый (от −100 до 0), более чувствителен к крайним значениям.
  • period 14; 5–40
  • oversold 80; 60–95
  • overbought 20; 5–40
  • qty 1; 1–10

RSI + Trend Filter реестр rsi_trend

Вход по RSI только В НАПРАВЛЕНИИ тренда (цена относительно EMA-фильтра) — откат RSI внутри тренда, не разворот против него.
  • rsi_period 14; 5–40
  • ema_period 50; 20–200 — фильтр тренда
  • oversold 40; 20–50
  • overbought 60; 50–80
  • qty 1; 1–10

Pivot Points Reversal реестр pivot_reversal

Классические floor-пивоты от вчерашних H/L/C: P=(H+L+C)/3, R1=2P−L, S1=2P−H (уровень 2: R2=P+(H−L), S2=P−(H−L)). Цена у поддержки — лонг, у сопротивления — шорт, между уровнями — выход.
  • level 1; 1–2 — 1=R1/S1 (ближние), 2=R2/S2 (дальние)
  • qty 1; 1–10

RSI Mean Reversion модуль rsi_mean_reversion

Эталонный standalone RSI на TF=5. RSI ниже oversold — вход в лонг фиксированным объёмом 1 контракт; выше overbought — закрытие лонга. Не переворачивает в шорт.
  • period 14; 5–100
  • oversold 30; 10–45
  • overbought 70; 55–90

Пробойные

Пробой канала волатильности (4 стратегии)#

Bollinger Breakout реестр bollinger_bo

Идёт ЗА пробоем полосы Боллинджера (в отличие от Mean-Reversion, которая идёт против). Пробой верхней полосы — лонг, нижней — шорт, внутри полосы — держим позицию без изменений.
  • period 20; 5–60
  • mult 20; 10–40 — сигма ×10
  • qty 1; 1–10

Bollinger Breakout M1 реестр bollinger_bo_m1

Та же логика входа, что у Bollinger Breakout, но с ПРИНУДИТЕЛЬНЫМ усреднением вместо стоп-лосса: усреднение включено с рождения (avg_max стартует с 5, avg_step_atr с 10 ×ATR/10), в отличие от базовой версии, где усреднение по умолчанию выключено и доступно как опция.
  • period / mult / qty — как у Bollinger Breakout
  • avg_max 5; 2–10 — форсировано включено
  • avg_step_atr 10; 5–30 — форсировано включено

Keltner Breakout реестр keltner_bo

Канал на EMA ± mult×ATR вместо SMA ± σ у Боллинджера — ATR лучше отражает реальный размер движения на волатильном FORTS. Пробой верхней границы — лонг, нижней — шорт.
  • ema_period 20; 5–60
  • atr_period 10; 5–40
  • mult 20; 10–40 — множитель ATR ×10
  • qty 1; 1–10

Donchian Channel Breakout модуль donchian_breakout

Turtle Trading System 1 (Dennis & Eckhardt, 1983). Только лонг: покупка при пробое N-барового максимума, продажа при пробое M-барового минимума (M < N). Классика, проверенная десятилетиями; для шортов на FORTS нужен отдельный доступ.
  • entry_period 20; 5–200 — пробой входа (N)
  • exit_period 10; 2–100 — пробой выхода (M)
  • qty 1; 1–10

ICT / smart-money

Порты из SkrimerForever/moex-trading-bot + собственная модификация (3 стратегии)#

Fair Value Gap (ICT) реестр fvg

3-барный ценовой разрыв: бычий FVG — low текущего бара выше high позапрошлого (импульс вверх, лонг); медвежий — зеркально. Подтверждение — тело текущей свечи в сторону разрыва не меньше min_frac (фильтр шума).
  • min_frac 5; 0–50 — мин. тело подтверждающей свечи ×10000 (5=0.05%)
  • qty 1; 1–10

Order Block (ICT) реестр order_block

Ищет импульсную свечу в последних lookback барах (|тело|/цена ≥ impulse_frac), зоной заказов считает последнюю ПРОТИВОПОЛОЖНУЮ свечу перед импульсом. Вход при возврате цены (ретест) в диапазон [low, high] этой зоны, в сторону импульса.
  • lookback 20; 5–60 — окно поиска импульса
  • impulse_frac 30; 5–100 — порог импульса ×10000 (30=0.3%)
  • qty 1; 1–10

US-Open Range + FVG/Ретест модуль us_open_fvg

ICT «Silver Bullet» + фильтр ложных пробоев из видео В. Дудукчанова «Свеча 9:30». Одна сделка в день от открытия биржи США (9:30 Нью-Йорк = 16:30 МСК при летнем времени США ~март–ноябрь, 17:30 зимой). Первая range_min-минутная свеча после открытия задаёт диапазон дня; вход по пробою с подтверждением FVG, по ретесту с отвержением, либо любому из двух; стоп/тейк как доля высоты диапазона, опциональный трейлинг вместо фиксированного тейка; принудительный флэт в 23:45 МСК.
  • open_hour / open_min 16 / 30 — час/минута открытия США в МСК (переключать при переводе часов в США)
  • range_min 5; 3–30 — длина опорной свечи
  • signal_min 60; 15–180 — окно входа после диапазона
  • entry_mode 1; 0–2 — 0=FVG+пробой, 1=ретест+отвержение, 2=любой
  • rr_x10 20; 5–50 — R:R ×10 (20=2:1)
  • stop_pct 0; −100–100 — стоп, % высоты диапазона от края
  • tp_trail / trail_act / trail_dist / trail_slip — опциональный трейлинг вместо фиксированного тейка
  • flatten_eod 1; 0/1 — флэт в 23:45 МСК, если TP/SL не сработали
  • allow_long / allow_short — разрешить лонги/шорты по отдельности
  • qty 1; 1–10

bar_offset_min — инфраструктурный параметр (0 в бэктест/STL, 180 при деплое на агент из-за разной эпохи баров), НЕ выведен в форму, никогда не участвует в переборе.

Универсальные модификаторы#

Усреднение, тейк, стоп-лосс, разножка, остывание, «долина смерти», ставки, суперусреднение, контр-стратегии#

Общая логика позиций make_on_bar добавляется КАЖДОЙ реестровой стратегии автоматически (по умолчанию выключена — поведение не меняется, пока параметр не тронут). Standalone-модули её не получают: у us_open_fvg своя собственная система стоп/тейк/трейлинг, у остальных модулей (донгиан, EMA/RSI-кроссовер, supertrend) управления позицией сверх чистого сигнала нет вовсе.

ПараметрВ форме UIЧто делает
avg_maxда (все реестровые)Максимум контрактов в позиции при усреднении. 1 = усреднение выключено.
avg_step_atrдаШаг усреднения в долях ATR ×10 (24 = 2.4×ATR хода против позиции). 0 = выключено. Докупает ТОЛЬКО против движения, никогда в плюс.
tp_atrдаТейк-профит от средней цены входа в долях ATR ×10. 0 = тейка нет, выход только по обратному сигналу.
avg_atr_nдаПериод ATR в барах М1 для тейка и шага усреднения.
sl_frac / sl_pctдаДва независимых стоп-лосса от средней входа: sl_frac — доля дистанции тейка в % (50 = половина пути; без тейка не работает), sl_pct — процент от цены входа ×100 (50 = 0.50%; от тейка и ATR не зависит). Включены оба — срабатывает ближний. Стоп проверяется РАНЬШЕ усреднения, фиксирует убыток для ставочной системы, и после срабатывания тот же сигнал не пускает обратно, пока тот не сменится или не пропадёт.
min_gap_ptsда«Разножка»: не доливать, пока цена не отошла от прошлого ИСПОЛНИВШЕГОСЯ входа минимум на N пунктов. Фильтр лестницы усреднения: вход с нуля не гейтит (правило 31.07.2026), выходы никогда не блокирует.
cooldown_min / cooldown_pctда«Остывание»: после выхода, зафиксировавшего движение ≥ cooldown_pct, новые входы блокируются на cooldown_min минут; на это время смена сигнала становится выходом в плоскую позицию, а не разворотом.
dv_bars / dv_range_ptsда«Долина смерти»: затяжной боковик в узком коридоре, где трендовый сигнал (MACD) пилит развороты и отдаёт депозит комиссией — а вход внутри коридора легко приходится на манипуляцию маркетмейкера. Детектор: размах ЗАКРЫТИЙ за dv_bars минутных баров меньше dv_range_pts пунктов (по закрытиям, не по high/low — фитиль долину не гасит, выводит из неё только устойчивый уход цены). В долине блокируются входы с нуля, обратная нога разворота и доборы (выходы — тейк, стоп, разворотное закрытие — работают всегда), а долинные бары ВЫРЕЗАЮТСЯ из серии перед расчётом сигнала: средние не сходятся за время боковика, и первый настоящий пробой оценивается против до-долинного тренда. Отсевы видны на карточке («Долина смерти отсеяла») и копятся в «Эффекте фильтров». Не сочетается со стратегиями на времени бара (pivot).
bet_step / bet_maxтолько у Shectory-2EMA, логика доступна любой реестровой стратегии через params_jsonСистема ставок: объём следующего входа растёт на bet_step после убыточной сделки (до потолка bet_max), сбрасывается к базовому после прибыльной.
super_y / super_zнет — только через params_json/APIСуперусреднение: после убыточного выхода растут И объём входа, И потолок усреднения (avg_max) на super_y контрактов, до super_z эскалаций; сброс после прибыльного выхода. Складывается с системой ставок.

Контр-стратегии __inv инверсия

Любая реестровая стратегия доступна в инвертированном виде: make_on_bar('<id>__inv') фейдит базовый сигнал (там, где база покупает — контра продаёт). На некоторых контрактах выгоднее фейдить сигнал, чем следовать ему. В Ботсторе и бэктесте такие роботы отображаются с пометкой «(контр)» у имени стратегии.
