13.09.2026: rf_gate.py (rich_fool) сопоставлял строки RIM6/RIU6 по ключу из всех параметров, включая d_coef. Но d_coef калибруется ОТДЕЛЬНО под каждый контракт (RIM6 216, RIU6 204 при одних F/n_days), так что вектор никогда не совпадал сам с собой на втором квартале. Гейт rf7/rf8/rf9 показывал «0 прошли», по этому нулю волна rf7 (500k) была остановлена как «нет пересечения кварталов» — артефакт.

**Why:** ноль от гейта выглядит как рыночный вывод, а был ошибкой соединения.

**How to apply:** в ключ сопоставления класть только СВОБОДНЫЕ оси; выводимые под контракт параметры исключать. Перед выводом «ноль совпадений» проверить руками один известный вектор на обоих контрактах (SQL по свободным осям). Связано: [[reference_confounded_axis]], [[project_rich_fool]].
