04.10.2026 оператор заказал страницу `/backtest/campaigns` (витрина всех кампаний бэктеста: название, идея, миниатюра кривой, статус, у каждой карточки свой URL, цепочка редакций; график как в TSLab: выше нуля мягкий зелёный, ниже мягкий красный). Спеки: `docs/campaign-showcase-spec.md` и `docs/backtest-workbench-spec.md` (редакции, кнопка «Создать новую редакцию», монитор с чатом Claude через oauth-Lineman, график против «купил и держи», топ-100 по RF × net × L, нормализация объёма до 1 млн полной стоимости). Данные собирает `scripts/campaign_showcase_build.py` по реестру `docs/campaigns/registry.json` (36 записей research) плюс 506 автозаведённых карточек optimizer (3 114 campaign_run в БД, это шарды, группа = дата + префикс имени); результат `~/apps/shectory-trader/data/campaign_showcase/` (index.json и по файлу на кампанию), с кривой только 35 карточек: `optimization_leaderboard` хранит метрики без сделок, кривые есть лишь у докатанных `<run>-bf<rank>` (49 кампаний, почти все июльские). Страницу, ручки и график делает окно ui-ux (frontend/, trader/api/), я отдаю данные; ts в кривой секунды unix, unit rub|points|pct (у optimizer выводится по point_value, эвристика, не проверена на выборке).

**Жёсткие требования оператора:** карточка = одна логика стратегии + один инструмент, переменные только параметры и период; объём без плеча (контрактов, ПОЛНАЯ стоимость, доходность от неё, ГО нигде); правку кода модель делает в отдельном воркере вне процесса STL, на ветке `wb/<карточка>/<ред>`, только `trader/lab/strategies` и тесты, ворота pytest+ruff+«позиция на конец дня 0», в main только после «принять». Воркер и Lineman требуют решения real-trade или оператора по месту (серверы сами не админим).

**How to apply:** новые идеи оформлять редакцией линии, а не отдельной кампанией; при добавлении кампании писать запись в реестр. См. [[reference-grid-sweep8-no-candidate]], [[reference-campaign-backfill]].
