В `agent_bars/<SECID>.json` на хостере пишут двое:
- `scripts/rf_fetch_contracts.py` — полная история контракта (~200 дней) для проб и бэктестов;
- `scripts/warm_robot_bars.py` — cron `0 5 * * *`, окно 75 дней для графика робота, только для
  ТЕКУЩИХ контрактов развёрнутых роботов (RIU6, SiU6 …).

До 13.09.2026 прогрев ПЕРЕЗАПИСЫВАЛ файл, и каждое утро голова ряда пропадала: RIU6/SiU6
начались с 30.06 вместо 19.06. Проба на хостере дала RIU6 8 577 против 57 624 в
лидерборде i9 на тех же параметрах — расхождение в данных, а не в коде.

Починено в 9fd8995: прогрев сливает (бары до первого свежего сохраняются). Тест
`tests/lab/test_warm_bars_merge.py`.

**How to apply:** проба на хостере расходится с лидербордом i9 — сначала сверь диапазон дат
и mtime файла в `agent_bars/`, потом ищи в коде. Файл с `mtime 05:00` = его трогал прогрев.
У `rf_fetch_contracts.py` для истёкших контрактов обязателен `SECID:YYYY-MM-DD`, иначе
окно «по сегодня» режет ряд (см. [[project-rich-fool]]).
