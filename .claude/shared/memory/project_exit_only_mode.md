28.07.2026. Запрос оператора: рядом с «Пауза» нужна кнопка «Только на выход» —
робот ждёт свой сигнал к закрытию (TP/SL) и не открывает новую позицию; «Пуск»
возвращает в работу. Пригодится на экспирации контракта, при разводе встречных
роботов (биржа отклоняет кросс-заявки) и перед выводом в бумагу. Пауза для этого
не годится: она замораживает робота ВМЕСТЕ с открытой позицией.

**Как сделано (без правки протокола!):** флаг `exit_only` живёт в `params_json`
робота — инфраструктурный параметр, как `bar_offset_min`. Едет штатным
`SetRobotParams`, переживает рестарт вместе со спекой, виден в зеркале
(`RobotStatus.params_json`), не требует перевыпуска proto-стабов.

- STL: `POST /api/v1/quik/robots/{id}/exit-only` `{agent_id, on}` — читает params
  ИЗ ЗЕРКАЛА, ставит/снимает флаг, шлёт SetRobotParams (не затирает настройки).
- Раннер (`robot_runner/runtime.py`, `place_order`): заявку, открывающую или
  увеличивающую позицию, наружу не пускает (`skipped-exitonly`); разворот через
  ноль УРЕЗАЕТ до закрытия (выходим, в противоположную сторону не встаём).
  `host.py` выставляет `rt.exit_only` из params перед каждым баром.
- UI: кнопка в AGENT-ROBOT рядом с «Пауза»; когда режим включён, на её месте
  «▶ Пуск». Тесты: `tests/runner/test_agent_runtime.py` (5 штук).

**Доставка:** раннер собран на Windows (`bash deploy/build_runner.sh`), sha
сверен, опубликован БЕЗ триггера — rev **1785256114**, агент применит в 03:00.
Чтобы включить раньше: `bash ~/quik_build/publish_quik_agent.sh 9618`.
