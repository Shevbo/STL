**Механика отравления:**
- После рестарта QUIK перезаливает «Таблицу всех сделок» С НАЧАЛА ДНЯ; тейп
  РЕПЛЕИТСЯ через файловую очередь (~30-40× реалтайм, `exchange_lag_ms` в
  health = отставание головы тейпа: было 30.5М мс = 8.5 часов, тает на глазах).
- Раннер строит бары из тейпа, и пока «тейп течёт», живые снапшот-тики
  ЗАГЛУШЕНЫ (правило mute) → бары несут ЦЕНЫ ~40-минутной давности (бар
  «23:13» с close 83260 при реальном рынке 84150).
- А bid/ask (getParamEx) — ЖИВЫЕ. Стратегия видит «провал» цены по барам →
  усреднение срабатывает каждый бар → раннер шлёт marketable BUY по РЕАЛЬНОМУ
  аску. Цикл: +1 контракт/минуту до max_position.
- Симптом на стенде: дико прыгают/огромны «лаг биржи» (миллионы мс) и «дрейф
  часов VDS» (NTP после ребута) — это и есть маркер реплея.

**Что делать при ЛЮБОМ рестарте QUIK/VDS (пока нет структурного фикса):**
1. СРАЗУ пауза всем реальным роботам (STL: POST /robots/{id}/pause-agent).
2. Ждать `health.exchange_lag_ms` < ~5000 (тейп догнал; смотреть в
   agent-local-status).
3. Проверить вменяемость баров: bar close ≈ bid/ask.
4. Снять с паузы. Пауза персистится в robots.json — сама не слетит.
