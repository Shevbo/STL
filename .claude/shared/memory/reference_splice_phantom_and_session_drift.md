Три ловушки данных, найденные 12.09.2026 при проверке rich_fool. Каждая по
отдельности способна выдать шум за преимущество.

## 1. Шов переката = фантомный итог. Гонять ПОКОНТРАКТНО

Непрерывные серии (`agent_bars/RI.json`, `Si.json`) сшиты через перекат БЕЗ
выравнивания базиса. В окне 2026-03-09..09-09 у RI ровно ОДИН скачок >=3%:
**01.07.2026, 105 250 -> 91 560, −13.01%**. Позиция, пережившая шов, получает
разницу базисов как «прибыль».

Цена ошибки: «лидер» ночного перебора rich_fool показал net 2 214 471 на 31
сделке. Поминутный разбор: шорт открыт 15.06 (набор 1->3->9->27->80 = 120
контрактов за ЧЕТЫРЕ минуты), закрыт 01.07 по 92 514 при средней 110 303. Одна
эта сделка = 2 134 680, то есть **96% всего итога**. Продал RIM6, «выкупил» RIU6.

Проверка: `scripts/rf_data_audit.py` печатает топ скачков открытия против
вчерашнего закрытия. Внутри одного контракта максимум 1.72% — швов нет.
Поконтрактные серии качает `scripts/rf_fetch_contracts.py` (напрямую с ISS).
Фронт-окна: RIM6/SiM6 2026-03-20..06-17, RIU6/SiU6 2026-06-19..09-09.

Альтернатива — `splice_rolls=1` в `run_single_backtest` (закрывается перед швом и
глушит прогрев новой серии), но поконтрактный прогон убирает класс ошибки целиком.

## 2. Расписание FORTS менялось ВНУТРИ периода — зашитый час открытия врёт

Первый бар буднего дня по данным ISS:
- RIM6 (март-июнь): 08:59 у 48 дней, 09:00 у 14, **07:00 НИ У ОДНОГО**;
- RIU6 (июнь-сентябрь): 06:59 у 27, 07:00 у 15, 08:59 у 17;
- SiM6: все 62 дня в 08:59.

Любая прописанная константа — и «07:00 утренняя сессия», и «10:00 основная» —
сдвигает «импульс открытия» на середину дня для половины истории. Решение без
заглядывания в будущее: **ОТКРЫТИЕ = первый бар дня** (лестница считается от
вчерашнего закрытия, значит выставляется до открытия и имеет право исполниться на
первом же баре), **ЗАКРЫТИЕ = последний бар предыдущего дня того же типа**
(будни/выходные раздельно). Запасные значения, если истории нет: будни 23:50,
выходные 19:00.

Выходные FORTS торгует: 38/38 дней имеют бары, первый 09:59, последний 18:59 —
то есть сессия 10:00-19:00. Подтверждает [[reference_forts_weekend_trading]].

**Побочный урок про себя:** я измерил «в кэше окно 07:00-07:30 есть в 42 днях из
155» и сделал вывод «утром слабо торгуется», после чего МОЛЧА переопределил
стратегию оператора из предоткрытийной в дневную и подвёл под это объяснение. Факт
касался ПОЛНОТЫ КЭША, а не биржи. Нарушено строгое правило
[[feedback_moex_schedule_truth]]. Если измерение противоречит постановке задачи —
это повод спросить, а не переписать задачу.

## 3. Кэш базовых кодов терял утреннюю сессию

`agent_bars/RI.json` (источник номер один для i9): 18 142 пропущенных минуты, дыры
во ВСЕХ 155 днях, окно 07:00-07:30 лишь в 42 днях. ISS эти бары отдаёт — проба
RIU6 за неделю: 344 бара в 07:xx, первый бар 06:59/07:00 каждый день. То есть
дефект сборки кэша, а не отсутствие торгов. Перекачивать с ISS поконтрактно.

## Обязательный порядок перед любым перебором с изменённой стратегией

1. push в git (файл обязан быть в `agent/update_manifest.txt`);
2. `INSERT INTO agent_control(key,value) VALUES('update_token', …) ON CONFLICT …`;
3. дождаться смены `applied_token` в `i9_heartbeat` — i9 исполняет СВОЮ копию кода,
   `scriptCode` задания это лишь `import`;
4. `--submit`;
5. на первом готовом задании сверить РАЗБРОС net по осям. Совпавший net И совпавшее
   число сделок = оси мертвы, см. [[reference_i9_axis_alive_probe]].
