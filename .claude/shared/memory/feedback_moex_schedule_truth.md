**STRICT.** Единый источник правды о расписании торгов MOEX (часы сессий, выходные,
праздники, доп. сессии выходного дня) — ОФИЦИАЛЬНАЯ страница биржи:
**https://www.moex.com/s1167** («Расписание торгов»; срочный рынок — вкладка/раздел
`/ru/derivatives/`).

**Why:** оператор ДВАЖДЫ ловил меня на неверном «биржа закрыта». 2026-07-25 — по
эмпирике SYSTIME (тикает после закрытия). 2026-07-26 — по `TRADE_SESSION_DATE` (это
дата КЛИРИНГА T+1, во время торгов всегда завтрашняя) сказал «выходной, до понедельника»
ПРЯМО ВО ВРЕМЯ торгов на миллиарды. Оба раза я ВЫДУМЫВАЛ логику вместо чтения расписания.

**How to apply:**
- НИКОГДА не заявляю «биржа закрыта / выходной / торгов нет» из одного поля, дня недели
  или самодельной эвристики. Сначала — официальное расписание (moex.com/s1167) И факт
  идущих сделок (`VALTODAY` миллиарды + свежесть `TIME` по нескольким инструментам ISS).
- FORTS торгует по выходным (доп. сессия выходного дня) — см. [[reference_forts_weekend_trading]].
- Оракул платформы (`trader/market_session.py`) держать на: официальном календаре
  нерабочих дней (ISS dailytable = машиночитаемая версия страницы) + факте сделок; поле
  `TRADE_SESSION_DATE` — только справочно (next_session), в решении open/closed НЕ участвует.
- Если оператор спрашивает про часы/расписание — открыть moex.com/s1167, а не отвечать
  по памяти. Тот же принцип, что [[reference_equity_curve_lies]]: доверяй факту, не полю.

**МАШИНОЧИТАЕМЫЙ ИСТОЧНИК (подложка страницы) — ISS `engines/futures.json`:**
- `session_schedule` — ТОЧНЫЕ окна сессий по датам: типы morning_session/main_session/
  evening_session/**weekend_session** (доп.сессия выходного) + oa_booking/clearing/
  settlement. ФАКТИЧЕСКАЯ дата окна в `time_from`/`time_till`, а НЕ в `trade_session_date`
  (там дата клиринга T+1 — на ней я дважды ошибся).
- `dailytable` — исключения по датам (is_work_day=0 = праздник; рабочая суббота =1).
- Реализовано в `trader/market_session.py` (2026-07-26, переписан начисто):
  `fetch_schedule()` тянет оба блока, `classify(now_ms, schedule)` = попал ли SYSTIME
  (часы биржи) в торговое окно сегодня. Поллер кэширует расписание на час. Пример: вс
  10:00-19:00 weekend_session; будни morning 07-10, main 10-19, evening 19-23:50.
- НЕ вернуться к эвристикам «now vs SYSTIME» или «TRADE_SESSION_DATE» — обе давали «бред».
