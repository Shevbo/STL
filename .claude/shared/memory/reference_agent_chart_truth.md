Экран робота (`AgentRobotScreen.svelte` + `BacktestChart.svelte`) три раза подряд врал по P&L (2026-07-22..23). Итоговая честная схема:

**Три источника, что где брать:**
- **Бейдж «P&L»** = раннер `realized_pnl` (ПУНКТЫ) × coef. Авторитет ПОЖИЗНЕННОГО реализованного с момента армирования (reset только при paper->real). Для lxk22: 67984 пт × 1.5695 = 106703 ₽.
- **Журнал `algo_trades`** = пофилловый gross/net, ведёт позицию/среднюю непрерывно, хранит ₽/пункт в строке. НО покрывает только то, что удалось дозаполнить из 200-хвоста раннера (для lxk22 — с 21.07, ~24k), а НЕ с армирования 17.07.
- **Форма графика** — из ЖУРНАЛА (реальные сделки, без липовых SL от replay обрезанного хвоста с середины позиции).

**Ловушка «ledgerFromFlat» (бит 2026-07-23):** журнал может «начинаться с флэта» (первая строка pos 0→1) и всё равно НЕ быть полной историей — робот наторговал ~82k до 21.07, вернулся в ноль, оттуда уцелел хвост. «С флэта» != «с армирования». Нельзя брать сумму журнала как итог графика — разошлось с бейджем в 5 раз (22392 vs 106703).

**ПРАВИЛО привязки конца кривой:**
- Бэктест (`engineNet` = result.net_profit): МАСШТАБ (raw уже ≈ engineNet по тем же сделкам, множитель снимает копеечный дрейф).
- Живой робот (`netOverride` = пожизненный realized раннера): СМЕЩЕНИЕ `v + (netOverride - rawEnd)`, НИКОГДА масштаб. Форма из журнала — это ОКНО сделок < пожизненного; смещение поднимает базовую линию к истинному итогу, сохраняя каждый шаг между сделками точным. Полный журнал -> смещение ≈0; обрезанный -> смещение = нераскрытая ранняя история.
- МАСШТАБ по netOverride запрещён: растягивал форму в день, которого не было (-30k->+104k из ниоткуда).

**РАННЮЮ ИСТОРИЮ ВОССТАНАВЛИВАЮТ ЛОГИ РАННЕРА — не спеши говорить «данные потеряны» (ошибся 2026-07-23).** У каждого робота есть текстовый лог (`docs/logs.zip`, на хостере `~/robot_logs/`), где КАЖДЫЙ филл: `TS [FILL] side qty @ price [(paper)] → позиция POS @ AVG, реализовано R п.`. РЕАЛЬНЫЙ филл — БЕЗ скобочного статуса (это единственный признак); `реализовано` = накопленный реализованный раннера в ПУНКТАХ, значит P&L филла = дельта этого поля. Строка `АРМИНГ paper->РЕАЛ` обнуляет и реализованный, и историю (раннер делает ровно так). Парсер `parse_runner_log()` в `trader/quik/algo_ledger.py`, заливка `scripts/backfill_from_logs.py --dir ~/robot_logs` (идемпотентно, ключ `lg:`, вставляет ТОЛЬКО филлы СТАРШЕ существующих строк журнала -> не задваивает).

Ключ дедупа ОБЯЗАН включать `pos_after`: у реверса два филла в одну секунду с той же ценой/объёмом/стороной (закрытие + открытие обратной ноги), без него 9 филлов схлопнулись.

**Что вскрылось 2026-07-23 (восстановлено 239 филлов):** роботы, торговавшие РЕАЛОМ и потом переведённые обратно в бумагу, отсутствовали в журнале ЦЕЛИКОМ (бэкфилл из зеркала брал только текущих реальных): bollm1 −70 080 ₽ (35 филлов, 14-17.07), fvg-v2 −31 298 ₽ (85 филлов). Плюс дыра lxk22 20-21.07 (+82 161 ₽). Настоящий итог всей реальной алготорговли = **+32 674 ₽**, а не «только победители». После заливки журнал lxk22 = 106 634 ₽ против бейджа 106 703 ₽ (разница 69 ₽ — округление комиссии).

**Дисциплина проверки (обжигался):** после любого фронт-деплоя СВЕРЯТЬ ЗАГРУЖЕННЫЙ бандл в браузере (`script[src]` hash) — index.html кэшируется, браузер держит старый бандл, «проверил живьём» на старом коде = ложь. Форсить `?_cb=<ts>`; оператору говорить про hard-refresh. И всегда брать сырые числа из mirror/ledger/params, а НЕ верить полю в снимке (stale heartbeat = frozen activity).
