`make_on_bar` на перевороте сигнала шлёт ДВЕ заявки подряд без паузы: выход всей
позицией, следом вход в новую сторону (`library.py`, ветка «Signal flip / flat»).
В бэктесте обе исполняются в одном баре — там это корректно и трогать нельзя
(паритет бэктест/реал). Вживую выход ещё висит на рынке, когда приходит вход, и QUIK
отвечает **«Обработка кросс-заявок блокирована»**. Вход теряется, робот остаётся в
флэте вместо разворота, а не в шорте.

Лечится на стороне РАННЕРА, а не стратегии: `AgentRuntime._await_opposite_clear`
ждёт до `_CROSS_WAIT_SEC` (5 с), пока встречная заявка по тому же инструменту сойдёт
с рынка, и только потом считает цену (за эти секунды рынок уходит — цену нельзя
брать до ожидания). По истечении отправляет как раньше: пропустить вход хуже, чем
рискнуть отказом, так теряется переворот целиком. Заявка в ТУ ЖЕ сторону (усреднение)
не ждёт никогда. Пинится `tests/runner/test_cross_wait.py`.

Почему всплыло только 05.08.2026: у живого macd_cross переворотов не было вовсе
(см. [[reference-macd-warmup-frozen-signal]]), отказов набралось 4 штуки за июль на
циклах тейк-закрытие + повторный вход. После починки прогрева переворотов ~25 в
сутки — без ожидания каждый второй вход умирал бы так.
