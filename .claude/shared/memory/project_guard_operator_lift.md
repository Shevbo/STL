03.10.2026 окно ui-ux разобрало жалобу оператора «кнопка «Обычный режим» не работает»: кнопка
работала, но защита сетки возвращала режим через проход, потому что условие (позиция −24 при лоте 7 =
3.43 уровня при пороге 3) оставалось верным. Оператор жал её трижды за день (11:46, 14:16, 18:18),
каждый раз с тем же результатом. Решение: оператор вправе переопределить защиту, но не навсегда.

Снятие режима оператором (`grid_guard_rebase`) задаёт ТОЧКУ ОТСЧЁТА: `g_guard_base` = позиция сетки в
этот момент, обнуляются счётчики касаний, момент включения защиты и срок перевзведения, сторона зоны
ставится по текущей цене (цена, уже стоящая за порогом, не новое касание). Защита по уровням считает
набор СВЕРХ точки; точка едет вслед за сокращением позиции, разворот и ноль её обнуляют. Сработает
снова, когда набор вырастет ещё на порог (для лота 7 и порога 3 это ещё 21 контракт) или цена снова
войдёт в зону. Выбор между «409 защита держит» и «приостановить насовсем» отвергнут: первое отказывает
человеку в его заявке, второе оставляет сетку без забытой защиты.

Число для экрана отдаёт движок: `g_guard_levels` (сырое отношение, как в журнале «3.43 из 3», null при
выключенном пороге) и `g_guard_from` (точка), одной и той же функцией, по которой решает защита
(`grid_guard_levels`, `grid_guard_base_now`). Экран свою копию правил удалил. Урок: правило, которое
повторено на экране «только для показа», расходится с движком вопрос времени; отдавать готовое число.
Тест: 40 путей против независимой модели «набор = |позиция| минус бегущий минимум с момента снятия».
