Стратегия `trader/lab/strategies/valley_spike.py` (коммиты 3b81759, 9309e75), постановка
оператора 13.09.2026: работать только в долине смерти; при включении долины замораживать
медленную среднюю ДО долины и ставить на её уровне дальнюю лимитную лестницу (формула
rich_fool D/(n+1)), тейк — возврат к середине долины. Честная по построению: всё, что решает о
заявке, известно до бара налива (урок [[reference-intrabar-fill-lookahead]]).

**Две находки механики:**
- Снятие лестницы на первом баре вне коридора давало НОЛЬ наливов (RIU6: 78 вооружённых долин
  при разрыве ≥50% свечи, 0 заявок): выброс на полсвечи (~1100 пт RI) одним баром не делается.
  Отсюда `ttl_bars`. Дальше 240 баров срок жизни ничего не меняет (240 = 1440 по результату).
- Проба с подменой детектора долины искажала частоту: «продлённая» долина блокирует вооружение
  новых. Мерить только на реализованном параметре.

**Проба 9309e75** (пункты, dv_bars 60, коридор 30% свечи, slow_n 400, 3 ступени, D 50%,
ret 50%, stop 25% свечи, max_hold 240), квартально RIM6/RIU6/RIM5/RIZ5 и Si те же:
- разрыв ≥50% свечи («очень дальние», как в постановке): 0-5 сделок за квартал. Не статистика.
- разрыв ≥25%, ttl 60-240: RI +2 135 / +21 168 / −6 535 / −15 818 при 16-27 сделках;
  Si +766 / +453 / −5 071 / −734 при 12-24. Порог 100 сделок не пройден нигде, знак 2 из 4.
- Плюс RIU6 — падающий квартал ([[reference-direction-not-edge]]).

**Статус:** гипотеза в этой форме не проходит гейт частоты — та же стена, что у
[[project-rich-fool]]. Не перебирать ту же сетку заново. Живые варианты, если оператор захочет:
пул инструментов (частота складывается), другое определение «дальнего», другая долина.
Для реала отдельно нужна выставляемая заранее лестница в раннере (зона real-trade).
