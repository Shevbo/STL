2026-07-26: один и тот же прогон (+724k) рисовал ДВЕ разные кривые — гладкую у лидера и качели ±2.5М у того же набора из избранного. Оператор в ужасе, отказ рисковать деньгами.

**Три наложенных бага в `frontend/src/components/lab/BacktestChart.svelte` + `BacktestLab.svelte`:**
1. **Символ брался из `paramValues.symbol` (текущий выбор в списке), а не из РЕЗУЛЬТАТА.** Открыл MXU6-избранное при выбранном RIM6 → грузились бары RIM6 под сделки MXU6. Фикс: `symbol = leaderResult.params?.symbol ?? result?.params?.symbol ?? paramValues.symbol`.
2. **Окно баров бралось из сохранённого `editFrom/editTo` избранного, а не из диапазона сделок.** Короткое окно (до 23.05) под сделки до 19.07 → часть сделок ЗА барами. Фикс: `liveWindow` (бэктест-ветка) расширяется до min/max времени сделок из `result.trades` (время сделки — unix-сек).
3. **КЛЮЧЕВОЕ — привязка кривой к итогу переворачивала форму.** Кривая строилась суммой закрытых P&L по барам; сделки после последнего бара ВЫПАДАЛИ из суммы → `rawEnd` частичный огрызок → множитель `engineNet/rawEnd` (задуман как копеечная поправка дрейфа) становился огромным/отрицательным → честный +724k рисовался как ±2.5М. Фиксы: (а) хвостовые сделки досыпаются в последнюю точку (`rawEnd`=полный итог); (б) масштаб применяется ТОЛЬКО при знак-совпадении и кратности [0.4, 2.5], иначе рисуем честный raw; (в) подпись «⚠ данные графика короче теста: N сделок сжаты».

**Правило:** график РЕЗУЛЬТАТА (лидер/избранное) обязан брать символ, окно и точку итога от самого результата/сделок, НЕ от текущего состояния UI. Любой множитель на кривой должен быть sanity-гейтнут — множитель ×(-14) на «поправке дрейфа» = ложь. Связано с [[reference_agent_chart_truth]], [[reference_point_coef_trap]].

Тестовый метод: создать избранное с run_id (сделки за пределами окна) + коротким date_to, открыть — кривая должна остаться гладкой (окно расширяется), символ верный, варнинга нет. Проверено через общий браузер (CDP).
