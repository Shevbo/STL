01.10.2026. Карантин после слепоты судил о наличии данных по инструментам ЖИВЫХ
заявок: `fresh_now = any(... for c in book.codes())`, а `book.codes()` берёт коды
только активных. В 08:01 по слову оператора я снял две осиротевшие заявки, книга
опустела, и `any()` по пустому множеству стал давать False на каждом проходе.
Отметка «последний раз видели рынок» замёрзла на 08:01:10, пока данные шли
непрерывно. В 10:07:40 оператор создал тейк, свежесть «вернулась», разрыв
посчитался в 7601 секунду — и ВХОД был задержан на полные три минуты карантина:
залилось в 10:10:41 вместо 10:07:5x. Починено (`d59c201`): нет кодов, за которыми
следим — считаем, что рынок видим.

**Why:** дефект заложен в карантине 25.09, но ВЗВЕЛО его моё собственное
действие — снятие заявок. Пустое множество прошло через `any()` молча, как и
всякое пустое множество: оно не ошибка, оно просто False.

**How to apply:** два правила. Первое: прежде чем снять последнюю живую сущность
(заявку, робота, подписку), спроси, что в системе считает её наличие признаком
здоровья. Второе, общее: `any()`/`all()` по коллекции, которая МОЖЕТ опустеть,
обязаны иметь явную ветку на пустоту — иначе «нечего проверять» молча становится
«проверка не прошла». Диагноз ищи по ТЕКСТУ события (`detail` в
`data/so_events/*.jsonl`), а не по его имени: сто двадцать одинаковых строк
`held` ничего не говорят, а их `detail` назвал причину сразу.
