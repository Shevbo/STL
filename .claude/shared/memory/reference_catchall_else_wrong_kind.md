30.09.2026 оператор написал: «Укажите заявку, за исполнением которой следим — это не хрена?» на экране коридора, кнопка «Взвести заявку» серая. Поле `watch_client_id` у коридора не спрашивают нигде, и взвести его было НЕЛЬЗЯ ВООБЩЕ — ни разу с момента выката новых типов. Причина: в `preview()` (`frontend/src/lib/smart-order-help.ts`) цепочка `if (kind === 'sl' …) else if (trail_tp) … else { /* on_fill */ }` заканчивалась catch-all `else`, написанным для «Зависимой». Новые `corridor` и `triangle` проваливались в неё и получали её проверку, её ошибку и её фразу.

Тесты этого не ловили, потому что проверяли каждый тип по отдельности, а не «каждый тип получает СВОЮ ветку». Симптом на экране тоже врал: текст ошибки был от чужого типа, и по нему искали ошибку не там.

**Правило:** в разборе по типу последняя ветка не имеет права быть безымянной. Каждый известный тип — своя `else if`, а финальный `else` говорит правду про незнакомый тип («тип … этот экран не умеет — обновите вкладку») вместо того, чтобы выдавать его за соседа. Добавили тип в union `Kind` — проверьте КАЖДЫЙ разбор по kind, а не только тот, который правите. В этом же файле такие разборы есть ещё в `smartLevels`, `keyPrice`, `conditionText`, `KIND_BY_ID`.

Тот же класс ошибки на сервере ловится иначе, чем на экране: там `_EMA_STRATEGIES` — явный список, и незнакомая стратегия честно даёт `ema_expected = false`.
