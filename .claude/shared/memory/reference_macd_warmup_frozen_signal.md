`make_on_bar` берёт окно `warmup(params)`; у `macd_cross` это было `slow + signal + 2`.
При `fast > slow` (живой robot lxk22tsffsxiiotb8kmpsato: fast=57, slow=48 -> окно 60)
окно едва длиннее самой длинной EMA, она не расходится с сигнальной линией, и знак
MACD залипает НАВСЕГДА.

Замер: окно 60 -> **0** переворотов за два месяца RIU6 M1; 120 -> 1453; 238 -> есть оба знака.

Подтверждено на реале 05.08.2026 по логу раннера за 6 суток: 778 закрытий лонга,
**ноль шортов**, 950 sell-заявок и все до одной — выход из лонга. Консоль при этом
писала «СИГНАЛ ШОРТ» 604 раза: `explain.py` считал сигнал по всему хвосту 600 баров,
а торгующий код — по окну 60. Диагностический признак ровно этот: монитор показывает
переворот, а в ту же секунду уходит заявка в противоположную сторону.

ПОЧИНЕНО 05.08.2026 (обе стороны расхождения):
- `macd_cross` прогрев -> `4 * max(fast, slow) + signal`, как у `macd_shectory1`;
- `explain.py` считает сигнал на `bars[-need:]`, а не на всём хвосте — консоль больше
  не может показывать сигнал, которого трейдер не видит.

ГЛАВНОЕ ПОСЛЕДСТВИЕ: все прогоны `macd_cross` до этой даты мерили не MACD, а
одностороннюю усредняющую машину с тейком. Параметры живого робота (+197 681 ₽ реала)
подобраны под залипший сигнал — с починкой это ДРУГАЯ стратегия, её надо перепрогнать
до постановки на реал. Признак старых прогонов в данных: одинаковый `max_mae` во всех
строках кампании и совпадающий до рубля результат у комбинаций, которые обязаны
отличаться.

ЗАМЕР 05.08.2026, RIU6 01.06-05.08, параметры усреднения живого робота, 365 комбо:
`fast > slow` (фейд) — 223 из 230 в плюсе, медиана +102 813 ₽; `fast < slow` (обычный
MACD) — 0 из 135 в плюсе, медиана −327 029 ₽. Живой конфиг 57/48/10 даёт +128 522 ₽
RF 0.90 против +229 963 ₽ RF 2.21 у соседнего 66/60/9. На RIU6 зарабатывает ТОЛЬКО фейд.

ВАЖНО: в половине `fast < slow` старое окно НЕ морозило (проверено, 0 из 64), поэтому
200 687 строк лидерборда macd_cross остаются в силе — заморозка била только по
`fast >= slow`, а сеточник эту половину вырезает как «вырожденную» (`valid_macd_config`).
Вырожден там лишь `fast == slow`; `fast > slow` — обычный осциллятор с обратным знаком,
и именно он прибыльный. Половина пространства macd не перебиралась НИКОГДА.

ВСЕ 14 роботов на macd_cross стояли на `fast >= slow`: 6 в вечном ЛОНГЕ (заморозка),
8 в вечном ШОРТЕ (`fast == slow`). Ни одного с `fast < slow`. Механизм отбора:
`scripts/deploy_winners.py` копирует params из лидерборда дословно и ранжирует по
net × RF — односторонняя поездка по тренду даёт максимальный net и высокий win rate,
поэтому сломанные конфиги систематически всплывали в топ. Любой авто-деплой
«победителей» из лидерборда, посчитанного на морозящем прогреве, отбирает баг.
