Три сессии Claude ведут один репозиторий по зонам (CLAUDE.md, «Three parallel
Claude windows»), и работу в чужой зоне надо ПЕРЕДАВАТЬ владельцу — раньше
оператор носил текст между окнами руками. Сделано 10.08.2026 (коммит 6c1821c).

- `trader/api/dev_msg.py`: `POST /api/v1/dev/msg`, `GET /api/v1/dev/inbox/{окно}`,
  `POST /api/v1/dev/msg/{id}/ack`, `GET /api/v1/dev/agents`.
- Окна: `real-trade`, `backtests`, `ui-ux`, `operator`, плюс `all`. Список
  ЗАКРЫТ: опечатка в адресате = письмо, которое никто не прочитает.
- Хранение — `agent_control` (key/value, `devmsg:<ms>:<rand>`), как
  `lab_favorites`: единицы писем в день, таблица и миграция не нужны, хвост 200.
- **Микропромпт едет ВНУТРИ ответа инбокса** (поле `prompt`): свежая сессия
  узнаёт протокол из самого ответа, а не из документации, которую могла не
  прочитать.
- CLI: `ssh hoster 'bash ~/apps/shectory-trader/scripts/devmsg.sh inbox <окно>'`
  (send / inbox / ack / board).
- **Будильник**: SessionStart-хук в `.claude/settings.json` проекта печатает
  доску непрочитанного при старте ЛЮБОГО окна. Хук не знает, какое окно
  стартовало (три сессии = один пользователь на одной машине), поэтому печатает
  всё, а читатель берёт своё. Без будильника pull-модель мертва: окно не
  «вспомнит» заглянуть в ящик.

**Why:** передача задачи через человека теряется и тормозит; ящик без будильника
не читают.
**How to apply:** нашёл работу в чужой зоне — письмо владельцу, а не правка.
Подтверждай `ack` только сделанное: неподтверждённое достаётся следующей сессии.
