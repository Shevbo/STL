04.10.2026, витрина кампаний бэктеста (страница `CampaignShowcase.svelte`, данные сборщика backtests). Первая версия форматировала все числа лидеров по единице КАРТОЧКИ, потому что в спеке единица одна на кампанию. Настоящие отчёты показали обратное: у каждого лидера собственное поле `unit`, и в десяти кампаниях лидеры одной карточки в разных единицах (рубли и пункты) — страница подписывала пункты рублями. Затем backtests сами опровергли свою эвристику «единица по point_value лидерборда»: выборка из 15 стратегий дала ошибку в 47% (рубли вместо пунктов). После пересборки единица ТОЛЬКО измеренная — у перепрогнанных лидеров (328 из ~80 тысяч, rub 171 и points 157), у остальных `unit: null`, и у 1514 карточек из 1609 тоже; их прежние числа «points 467 / rub 75» недействительны.

**Правило, которое легко сломать:** `leaderUnit(l, cardUnit)` различает «поля `unit` у лидера нет вовсе» (старый сборщик, берём единицу карточки) и «поле есть и равно `null`» (единица НЕ определена). Подстановка единицы карточки на место `null` повторила бы ровно ту ошибку, которую backtests только что убрали у себя. Для `null`: число печатается без единицы, под таблицей «единица не определена (перепрогон не запускался)», на карточке витрины net помечен «?».

**Сортировка денежных колонок блокируется** (`unitState().blockMoneySort`) в трёх случаях: известные единицы разные; известная вперемешку с неопределённой; ВСЕ неопределены — это не «одна единица», а «неизвестно что», и «наибольший net» между пунктами и рублями число без смысла. Неденежные колонки (rf, контракты) сортируются как обычно, пустые значения всегда внизу.

**Источник доли L** (`l_share_source`): `curve` — измерено по месячному net кривой перепрогона, `leaderboard_windows` — ОЦЕНКА по окнам лидерборда (доля окон, не месяцев). Строки с разным источником несопоставимы, поэтому у оценки значок ≈ с подсказкой, а при смеси в одном отчёте сортировка по L и по `score = rf × net × l_share` отключена. Контрольный пример на живых данных: `opz-20260924-macd-shectory1-ri` (unit {null, rub}, источники {curve, leaderboard_windows}) — срабатывают оба предупреждения.

Общий урок: ПОЛЕ, ВЫВЕДЕННОЕ ЭВРИСТИКОЙ, ВЫГЛЯДИТ КАК ИЗМЕРЕННОЕ. Единица по point_value и L по окнам лидерборда читались на экране ровно так же, как настоящие, и разошлись с правдой в половине строк. Экран обязан отличать «измерено / оценено / неизвестно» там, где источник это различает.
