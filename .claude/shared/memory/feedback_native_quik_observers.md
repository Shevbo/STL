15.09.2026 оператор решил перейти на нативные стоп-заявки QUIK (стоп, тейк, трейлинг, связка, «по исполнению») вместо сторожа STL. Механика QUIK у нас не проверена: наблюдателей ставить МНОГО (сверка зеркала с таблицей stop_orders, каждый переход события, расхождение намерения и факта, сроки, счётчик транзакций), каждый отключаемый флагом позже. Демо-счёта нет: проверки на реальном счёте на дешёвом GZ по 1 контракту.

**Why:** 15.09 догонялка по ISS купила 5 RIU6 на ~580 п. хуже плана; стоп/тейк стояли вне сетки шага (87442). Оператор требует работу на секундах и видимость в самом QUIK.

**How to apply:** каждая серия проверок на GZ — реальные заявки, только с явного разрешения оператора и при нём. Нехватка ГО при постановке = отказ с красной тревогой. Сроки стоп-заявок синхронизировать с QUIK и регулярно сверять. Роботы и ручные — вместе. Цены только на сетке шага. Лимит транзакций: [[reference_broker_tx_rate_penalty]]. Проект: docs/design/execution-module.md.
