04.10.2026 в 10:54:13 по GZZ6 (сетка `def3ff351f`, лот 7, база 9969, шаг 10) уровни 0 (9969) и +1 (9979)
продали в одну секунду, уровень 0 проснулся от исполнения соседа, и в 10:54:15 сторож поставил на него
продажу по той же цене: к моменту постановки цена уже вернулась ниже 9969, а сторона живого уровня
выбирается по цене в момент постановки (`grid_side_for`: выше рынка продаёт, ниже покупает). Оператор
назвал это багом: повтор той же стороны без встречной сделки копит позицию в одну сторону.

Правило (коммит «уровень не повторяет ту же сторону»): `grid_repeat_blocked(live, level, side)`. Уровень,
последний раз исполнившийся продажей, снова встаёт продажей, лишь когда в сетке с тех пор исполнилась
покупка, и наоборот. Встать встречной стороной можно сразу. В состоянии сетки лежат только целые числа:
`ls:<уровень>` сторона (1 покупка, 2 продажа), `lo:<уровень>` сколько встречных заявок было на тот
момент, `cs:buy` и `cs:sell` счётчики; строки в `live` нельзя, `_cancel_resting` примет их за client_id.
Стоящая заявка, нарушающая правило, снимается сторожем (одна на строку раз в 30 с). При выкате живые сетки
засеяны историей по сделкам (сидер проигрывает сделки с тегом `stl-so-<so_id>` через `grid_note_fill`).
Выкат 11:16: снята одна продажа 7 по 9969, больше ничего не менялось.

Граница риска до правила: защита сетки по уровням (у GZ порог 14 уровней = 98 контрактов, около 977 тыс ₽
номинала, 1 ₽ за пункт на контракт, то есть 100 пунктов против = 9 800 ₽). Цена правила: после быстрого
скачка уровень может на время остаться без продажи, пока не исполнится покупка; это выбрано
сознательно в пользу безопасности. Тест: 60 случайных историй против независимой модели плюс повтор
инцидента через сторожа. Связано: [[reference-grid-stale-flags-and-partial-fills]],
[[project-grid-protection-trigger]].
