`varmargin` из QUIK futures_limits — это НЕ результат робота и НЕ результат дня
по журналу. Это финрез ВСЕГО СЧЁТА за торговый день FORTS (с вечернего клиринга
19:00), включая сделки оператора руками и детей умных заявок, и он ВАЛОВЫЙ
(комиссия отдельно, `ts_comission`).

04.09.2026 оператор увидел ВМ +16 248 ₽ против +5 074 ₽ по роботам и решил, что
врёт учёт робота. Врал не учёт: ~11 тысяч он сделал сам (покупка 8 @82430 из
терминала, продажи 3 @82600 и 5 @82690 детьми trail_tp). Увидеть это было
негде — журнал `algo_trades` знает только роботов, а статус агента отдаёт лишь
последние 100 сделок QUIK (`quikTradesCap`).

Починка: агент считает разбивку сам, блок `day` (`internal/status/daypnl.go`).
Финрез участника = `coef*(cash + net_end*last − net_start*base)`, тождественно
привычному «фикс + переоценка». Расчётная цена клиринга QLua не публикуется —
РЕШАЕТСЯ из ВМ, которую QUIK уже отдал по инструменту, поэтому сумма участников
равна ВМ счёта до копейки при любом окне. Окно — MSK-полночь: QUIK датирует
вечерние сделки следующим торговым днём, и оно само совпадает с окном ВМ.

ЛОВУШКА ТЕГА. QUIK хранит brokerref шириной 20 символов, длинный robot_id
приезжает обратно обрезком (`lxk22tsffsxiiotb8kmpsato` -> `lxk22tsffsxiiotb8kmp`).
Сравнение с полным ID не совпадает НИКОГДА: 05.09.2026 в первом же боевом
прогоне оба живых робота показались «приложением брокера». Сверять только через
`quikTag`/`[:20]` — recon это знал давно (`recon.maxBrokerrefLen`).

Торговля мимо агента (терминал QUIK, мобильное приложение Finam) идёт без тега.
Незнакомый НЕПУСТОЙ тег считаем «прочим», а не роботом: приложение брокера
вправе поставить свой brokerref, и трактовка «есть тег = робот» приписала бы
сделку оператора роботу.

Сверять «сегодня» роботов с ВМ можно ТОЛЬКО вместе с «Итогом ручных».
