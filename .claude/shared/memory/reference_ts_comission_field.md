02.10.2026 оператор спросил, почему QUIK пишет биржевые сборы около 900 ₽ при сотнях лотов. Внутри дня
поле `ts_comission` (в агентском статусе `health.money`, оно же `accruedint`) росло редкими ступеньками
ровно по 9.43 ₽, одной на лот по полной ставке: 914.71 ₽ при 593 проторгованных лотах. В 23:52 снимок
дня показал 990.15 = 105 × 9.43, то есть учтено 105 лотов из ~685. Мой прогноз «итог к концу дня около
2.9 тыс по скальперской ставке» НЕ сбылся. Счёт между вечерами двигался на 17 951 ₽, а вариационная
маржа плюс это поле дают 18 259 ₽: скрытого списания на ~2.6 тыс нет, значит либо внутридневные круги
стоят почти ничего, либо списание придёт позже отдельной строкой. Различит только отчёт брокера.

Справочные ставки биржи (ISS, `BUYSELLFEE` / `SCALPERFEE`): RIZ6 9.43 / 4.72, GZZ6 1.98 / 0.99,
скальперская ровно половина. В таблице сделок QUIK есть построчная комиссия: у оператора 13.72 ₽ за
сделку на 7 лотов GZZ6 = 1.96 ₽ за лот, обе сделки открывающие, ставка почти полная. Lua-скрипт эти
поля уже получает (`exchange_comission`, `clearing_comission`, `tech_center_comission`,
`broker_comission` в `emit_trade`), но Go-агент их выбрасывает: приём в агенте не доделан
(`SetTradeFee` и `FeeTotals` в accounts.go лежат неподключёнными).

Что НЕ делать: объяснять расхождение «скидкой скальпера» (запрет оператора 01.10) и называть поле
итогом до вечерней сессии. Связано: [[reference-commission-scalper-discount]], [[reference-commission-model]].
