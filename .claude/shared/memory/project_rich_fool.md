Гипотеза оператора 09.09.2026: за 10 мин до открытия сессии выставить лестницу
стоп-заявок вверх/вниз на долю амплитуды за N дней от вчерашнего закрытия; держать
30 мин; исполнилось → тейк/стоп 2:1; позиция носится овернайт.

Реализовано: `trader/lab/strategies/rich_fool.py` (standalone-модуль по образцу
us_open_fvg), коммит 8811e31. Тест `tests/lab/test_rich_fool.py`. В манифесте i9.
Прогон `scripts/queue_rich_fool.py`: RI+Si, 2026-03-09..09-09, 6480 комбо, оси
n_days/dist_pct/step_count/step_gap_pct/sl_pct/rr_x10/invert/open_hour{7,10}.

**ИТОГ 10.09.2026 после большого перебора (61 440 комбо, RI+Si, все оси до
step_count=25 / n_days=30, vol_mult ×2, нелинейная расстановка spacing/span, оценка
по критерию оператора: НЕ число сделок, а RF≥3 + окна WF + 2-й контракт + не край):
СЕМЕЙСТВО ИСЧЕРПАНО, кандидата нет.**

- **07:00 (гипотеза оператора) — мёртв.** Макс 13-14 сделок за полгода. Утренняя
  сессия не пробивает лестницу достаточно часто. step_count>4 инертен (дальние
  ступени не срабатывают).
- **10:00 (осн. сессия) — есть строки RF 28-60 при 30-120 сделках и 4/4 окна WF,
  но это мираж:**
  - `max_mae` ИДЕНТИЧЕН (2843₽ Si / 12357₽ RI) по десяткам конфигов → почти один
    набор сделок, RF = net ÷ одна плохая сделка.
  - Помесячно: весь плюс в ОДНОМ месяце из 7 (Si +165k = `[+0..+149835]`,
    RI +136k = `[-9767..+122615]`, 3/7 месяцев в плюсе).
  - Шаг с края сетки убивает: Si n_days 5→10 роняет net +165k→+17k; RI sl_pct
    35→20 и rr 25→15 уходят в МИНУС (−427, −591).
  - 2-й контракт: SiM6 +8-10k против SiU6 +165k, RIM6 +2.9k против RIU6 +136k —
    не воспроизведение, а положительный шум ~5% размера.

Дальше эту стратегию не крутить. Инфраструктура (модуль + оси + queue-скрипты)
в git на случай новой идеи по механике.

- open_hour=7 (как в гипотезе): 11-13 сделок / 6 мес, net ~6-10k. Пусто.
- open_hour=10 (осн. сессия): до 52 сделок, лучший net 49k — но это 31 сделка, и
  ВСЕ выигрышные параметры уперты в край сетки (dist=65 max, sl=45 max, rr=30 max,
  n_days=8 max). Переобучение на несколько пробойных дней.
- invert (фейд) vs пробой: фейд чуть лучше на 7:00 (обе тривиальны), разницы по
  сути нет — стена это число сделок для обеих.

BR исключён из прогона: непрерывный загрузчик `load_bars_iss("BR",...)` отдаёт ОДИН
день на многонедельный запрос, и BR-сессия открывается ~09:00 (первый бар hm=539),
не 07:00. Отдельный баг загрузчика, если понадобится BR.
