Раннер копит realized_pnl в ПУНКТАХ ЦЕНЫ. UI переводит в рубли через coef = step_cost/price_step из QLua-фида (`/api/v1/quik/params`). Реальные коэффициенты (2026-07-22): BRU6 = 785.54, RIU6 = 1.57108, GZU6/SiU6/SRU6 = 1.0.

**Ловушка (бит 2026-07-22, найдено оператором):** в `AgentRobotScreen.svelte` coef хранился голым числом. Карточка монтируется ДО загрузки робота (symbol = другой инструмент), coef резолвится для него; когда резолв для своего символа не доезжал (таймаут / поздний ответ, отбитый guard-ом `sym === symbol`), оставалось значение ПРЕДЫДУЩЕГО инструмента. Итог: BRU6-робот показывал -7.11 пт × 1.57108 (коэф RTS) = «-11 ₽» вместо × 785.54 = -5 585 ₽. Занижение реального убытка в 500 раз; вся колонка P&L по сделкам врала так же. Фикс: coef хранится ВМЕСТЕ со своим символом (`coefFor = {sym, coef}`), читается только при совпадении с текущим; неизвестный coef = НЕ показывать рубли вообще, ретрай 15с, подпись оси «пункты».

**Правило на будущее:** `pointValue = 1` НЕ означает «коэффициент неизвестен» — для GZ/Si/SR это настоящий коэффициент. Отличать только явным флагом (`pointValueKnown`), никогда по величине. Любой фолбэк `coef ?? 1` в денежном пути = молча выдать пункты за рубли.

**Кросс-проверка:** журнал `algo_trades` хранит point_value В СТРОКЕ на момент инжеста и считает независимо от UI — при сомнении в цифре карточки сверять с «Доходность (журнал)»/API `algo-report`. 2026-07-22 журнал был прав (-6 436 ₽), карточка врала.

**Ошибка диагностики того же дня (не повторять):** `curl -H "X-Agent-Token: ..."` к `/api/v1/quik/params` и `/robots-mirror` отдаёт `{"detail":"Unauthorized"}` (нужен session Bearer). `json.get("rows", [])` на этом ответе даёт `[]` и читается как «фид пуст». Проверять зеркала через аутентифицированный браузер (CDP) или session-токен, и всегда смотреть сырой ответ, а не только распарсенное поле.
