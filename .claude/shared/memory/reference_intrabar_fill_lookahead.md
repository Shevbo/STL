Урок impulse_fade 13.09.2026 ([[reference-impulse-fade-mirror]]), общий для любой стратегии,
которая сама назначает цену филла через `place_order_at`.

**1. У живого раннера стоп-заявок нет.** `robot_runner/runtime.py` place_order_at = обычная заявка
по цене. Покупка ВЫШЕ рынка «по уровню» внутри бара нереализуема. Реализуемо: заметить событие
по ЗАКРЫТОМУ бару и войти по открытию следующего — это `BacktestRuntime.place_order`
(на последнем баре безопасно: advance() останавливается на len-2).
Лимитник ПРОТИВ движения (продажа выше рынка, стоящая заранее) — реализуем по своему уровню.

**2. Фильтр по экстремуму бара при филле в том же баре = заглядывание в будущее.** Если заявка
налита внутри бара, всё, что решает о её исполнении, должно быть известно ДО бара (уровень,
закрытия прошлых баров). `cur.high`/`cur.low` можно использовать только для решений, исполняемых
на СЛЕДУЮЩЕМ баре.

**3. Проскальзывание мерить фитилём, а не ATR.** 0.25·ATR(200) M1 на RI = 14-23 пт (1-2 тика),
медиана фитиля бара входа за этой ценой 110-160 пт (p90 310-430). Стресс на ATR-долях ниже
медианы фитиля «ничего не меняет» и успокаивает ложно.

**4. Переживший OOS отбор ≠ эдж.** Перестановка по векторам доказывает устойчивость ОБЛАСТИ
параметров, а систематический артефакт исполнения устойчив во всех кварталах так же. Подпись:
корреляция IS↔OOS по параметрам 0.6-0.9, лидеры на краях сетки, «эдж» растёт монотонно к краю,
почти все выходы по времени. Тогда сначала проверять исполнение, потом статистику.

**How to apply:** перед переносом кандидата наверх — (а) каждый place_order_at пробойного типа
заменить на вход по открытию следующего бара и перемерить; (б) grep `cur.high|cur.low` в гейтах
входа; (в) денежный вывод — субагенту ([[feedback-validate-money-with-fable]]).
rich_fool тоже исполняет стоп-лестницы через place_order_at — проверить тем же приёмом.
