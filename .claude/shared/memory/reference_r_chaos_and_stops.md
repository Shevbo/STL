Идея оператора: каждая R-я сделка против сигнала — «хаос для манипулятора». Параметр
`r_inv_every` в make_on_bar (00302cd), по умолчанию 0. Прогон rch: лидеры 18 стратегий
реестра (выбраны в выборке, чаще на U6) на M6+U6, R {0,2,3,5,10}. Прогон stp: те же + __inv,
sl_pct {0, 0.5, 1, 2%}.

**Итог (обсуждено с fable): пользы нет ни у R, ни у стопов.** R лучше R=0 в меньшинстве
(R2 6/24 … R10 13/34), медиана разницы отрицательная и растёт с частотой инверсии — это доза
возмущения подогнанной строки, не свойство хаоса; «+» втрое чаще на M6 (вне окна отбора) =
регрессия к среднему. Стоп 0.5% лучше 27 / хуже 32 / не сработал 13 из 72; у стратегий с
тысячами сделок (rsi_trend, stochastic, williams_r, bollinger_mr __inv) стоп НЕ СРАБАТЫВАЕТ —
флип быстрее, это «не проверено», а не «не помогает».

**Ловушки, которые вскрылись:**
- У всегда-в-рынке стратегий инверсия R-й сделки = пропуск двух переворотов; R=2 на
  чередующемся сигнале = вечная позиция (bollinger_bo_m1: 0 сделок, net 0).
- net лидерборда считает только закрытые сделки. Любая ось, меняющая «стоит ли робот в
  позиции на конце окна» (R, стоп, фильтры), обязана мериться mark-to-market по последнему
  close; отсев клеток «мало сделок» = отсев по переменной, которую ось и меняет.
- Детерминированная «каждая R-я» не хаос — выучивается. Честная проверка: три ветки на одной
  частоте 1/R (инверсия R-й, случайная инверсия по seed, случайный ПРОПУСК) — отделяет
  «испортили подогнанное» от «инверсная сделка сама убыточна».
- Гипотеза «ломаем ожидания манипулятора» бэктестом непроверяема (исполнение по close не
  реагирует на наши заявки); на 1-2 контрактах RI поток никто не читает. Единственный
  признак — проскальзывание по пофилловому algo_trades, растущее с предсказуемостью.
