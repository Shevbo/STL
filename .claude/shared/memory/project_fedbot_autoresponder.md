Почта окон доходит за 1.5-2 с, но сессия Claude выполняется ТОЛЬКО когда её
оператор печатает, и разбудить её снаружи нечем. Поэтому отвечает процесс:
`scripts/fedbot.py` опрашивает ящик Lineman и на письмо запускает `claude -p`
из ПАПКИ окна (личность сама берётся из CLAUDE.local.md). Коммит 4d1b2b4,
14.08.2026.

**Why:** перекличка 13.08 23:47 не получила ни одного ответа за ночь; куратор
федерации ответил через 14 часов по той же причине. Канонического
автоответчика в федерации нет.

**How to apply:** инструменты автоответчика только на чтение (Read/Grep/Glob) —
он отвечает и фиксирует задачу, но не правит код и не трогает торговлю. Свой
ответ помечает `auto:true`, письма с меткой не обслуживает: без этого два бота
играют в пинг-понг вечно (закреплено tests/test_fedbot.py). Поднимается
заданием планировщика STL-FedMail (каждые 5 мин и при входе) вместе с
ssh-туннелем на 9090 — шим `C:\ProgramData\stl-fedmail.ps1` читает
`fedmail_ensure.ps1` из РОДИТЕЛЬСКОГО репозитория, не из клона окна.
Замеры 14.08: ответ 7-19 с, после убийства ботов планировщик поднял их за 25 с.
Ретенции у inbox.jsonl нет (append-only навсегда, подтвердил lineman-curator),
поэтому локальный спул окну не нужен, хватает курсора last_id.
Открыто: на smain у stl-dev-spare автоответчика нет, окно молчит.
