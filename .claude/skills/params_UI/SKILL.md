# params_UI — единый фрейм параметров робота

Фрейм параметров в STL один и тот же везде, где параметры видно или правят: реал,
paper, бэктест. Это не стилевое пожелание, а требование к чтению: оператор меняет
значения на живых деньгах и не должен переучиваться между экранами.

## Что уже построено (не переписывать)

| Файл | Роль |
|---|---|
| `frontend/src/lib/param-groups.ts` | смысловые группы, бинарные ключи, ограничивающие ключи, шаг стрелки |
| `frontend/src/components/lab/ParamPanel.svelte` | сам фрейм: группы, значения, переключатели, стрелки, перевод |
| `frontend/src/components/lab/ParamEditor.svelte` | переключатель «Список / Панель», выбор запоминается |
| `frontend/src/lib/strategy-help.ts` | `helpFor(strategyId, key)` → `{title, what, short, live(v, ctx)}` |

Новый робот НЕ требует нового компонента. Он требует, чтобы его параметры были
описаны в этих двух местах.

## Скрипт работы

### 1. Собрать факты о роботе

```bash
# Параметры, которые реально стоят (агентский и бумажный — одна ручка)
ssh hoster 'cd ~/apps/shectory-trader && set -a; . ~/.shectory_trade.env; set +a; \
  PY=$(/home/ubuntu/.local/bin/poetry env info --path)/bin/python; \
  TK=$($PY -c "import os;from trader.auth.portal import make_session_token as m;print(m(\"<email>\",os.environ[\"SHECTORY_AUTH_BRIDGE_SECRET\"]))"); \
  curl -s -H "Authorization: Bearer $TK" localhost:8000/api/v1/lab/robot-stand/<ID>'
```

Взять оттуда `strategy_id` и **все** ключи `params_json`.

### 2. Проверить покрытие групп

Каждый ключ обязан попасть в свою группу `GROUPS` (`param-groups.ts`). Порядок групп —
порядок вопросов оператора к роботу, менять его нельзя:

1. **Сигнал** — по чему робот решает, куда становиться
2. **Объём и лестница** — сколько контрактов и как добирает
3. **Выходы** — чем закрывает позицию
4. **Частота** — что тормозит вход и доборы
5. **Разрешения** — какие стороны открыты

Ключ вне групп уходит в «Прочее». Это не ошибка, но и не цель: если параметр
осмысленный, его место в своей группе.

Отметить в наборах:
- `BINARY` — поля 0/1 (рисуются переключателем, а не полем ввода);
- `BOUNDING` — параметры, повышение которых ОГРАНИЧИВАЕТ робота (стоп, паузы,
  разножка). Помечаются полосой: в одном столбце соседствуют «добирай больше» и
  «стой дольше», на глаз они неразличимы.

### 3. Написать пояснение и перевод

В `strategy-help.ts` для каждого нового ключа:

```ts
{ title: 'Человеческое имя',
  short: 'одна строка для подсказки',
  what: 'что делает, простыми словами',
  live: (v, ctx) => v ? `${v / 10}×ATR ≈ ${Math.round(v / 10 * ctx.atr)} пунктов` : null }
```

`live` — **главное в фрейме**. Сырое `tp_atr = 4` не значит ничего; `0.4×ATR ≈
6 пунктов` читается сразу. Если перевод невозможен, вернуть `null` — панель покажет
допустимый диапазон, а не выдумку.

### 4. Проверить

```bash
cd frontend && node ./node_modules/vitest/vitest.mjs run src/lib/param-groups.test.ts
cd frontend && node ./node_modules/vite/bin/vite.js build
```

Тест пинит инвариант: **группировка не теряет ни одного поля**. Невидимый параметр
продолжает влиять на живого робота — молча спрятать его страшнее, чем показать
некрасиво.

Затем открыть стенд робота и убедиться глазами:
- подписи не обрезаны;
- бинарные — переключателем, а не текстом `true`;
- под каждым значением есть перевод либо диапазон;
- служебные флаги вне схемы (`exit_only`) видны и помечены.

## Правила фрейма (нарушать нельзя)

**Показывать ВСЁ, что несёт робот.** Схема стратегии — не полный список:
инфраструктурные флаги (`exit_only`, `bar_offset_min`) в неё не входят по замыслу.
05.08.2026 из-за их невидимости правка `qty`/`avg_max` у РЕАЛЬНОГО робота молча
снесла `exit_only=true` и `allow_short=0`, и он снова начал открывать позиции.

**Показывать, что уедет роботу.** Строка изменений против текущих значений — по всем
ключам, а не только по тронутым руками.

**Никогда не заменять параметры целиком.** Сохранение накладывается на текущие
(`trader/api/quik_robots.py`, `relay_robot_params`). Неупомянутый ключ сохраняется.

**Перевод, а не украшение.** В фрейме нет ни одного декоративного элемента. Если
строка не помогает прочитать значение — её там быть не должно.

## Типографика и цвет (эталон)

Менять только вместе со всеми экранами сразу.

```
значение   22px ui-monospace, tabular-nums, #ffffff
подпись    14px/600 system-ui, #dfe8f7
перевод    12px system-ui, #7c8cab   (ограничивающий — #c79b5e)
фон        #0a1020    рейки #1c2a46
включено   #46c46a    ограничение #f0a83c
стрелки    34px цель мыши, автоповтор при удержании
```

## Что делает агент по вызову

`/params_UI <робот>`:

1. снимает параметры робота ручкой `robot-stand`;
2. сверяет каждый ключ с `GROUPS`, `BINARY`, `BOUNDING`;
3. дописывает недостающие ключи в `param-groups.ts` и пояснения с `live` в
   `strategy-help.ts`;
4. гоняет тест группировки и сборку;
5. отчитывается таблицей: ключ → группа → перевод, и отдельно списком то, что
   осталось в «Прочем» и почему.

Компоненты фрейма при этом НЕ трогаются. Если задача требует их править — значит
меняется эталон, и менять его надо для всех экранов сразу, а не для одного робота.
